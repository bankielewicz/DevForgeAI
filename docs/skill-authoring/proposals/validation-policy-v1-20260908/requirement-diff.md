The shared authoring contract's “Common authoring workflow” and “Three separately reported evaluation tiers” would need a coordinated clarification: Full retains the release convention; Routine is a separately labeled change-verification policy. Its isolation, provider, packaging, budget and evidence obligations are preserved. No shared contract is edited by this proposal, and live concurrent shared-contract revisions are not silently adopted.

After acceptance, the affected canonical implementation surface would include the validator SKILL.md; native-evaluation, ai-review-rubric, results-contract and enforcement references; plan/results/coverage assets; the reducer and its applicable deterministic regression fixtures; managed runtime predicates in their separate owner repository; and package derivation records. Exact files and independent checks must be allocated before implementation. This is an ownership map, not permission to edit all listed surfaces now.

All current mandatory cases remain intact until explicit acceptance. Even after acceptance, keep the complete case catalog: Routine selects a justified subset in a new plan, while Full uses every applicable case. Original assertions are never quietly replaced with pilot assertions.

Review decisions should record each VPR item as accepted, rejected or deferred. Partial acceptance is non-operative until conflicts between selected items are resolved in a new frozen revision. In particular, VPR-02 cannot operate without VPR-01, VPR-06, VPR-07 and the required versioned implementation described in VPR-11.

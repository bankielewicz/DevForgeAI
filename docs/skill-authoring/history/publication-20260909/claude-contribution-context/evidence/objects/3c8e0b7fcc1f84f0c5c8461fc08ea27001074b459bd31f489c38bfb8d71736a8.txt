# Project expert specification

Record the project, role, concrete goal, and upstream decision revisions.

| Contract | Required content |
| --- | --- |
| Responsibility | Outcome owned by this role and limits of that responsibility. |
| Activation | Requests requiring the skill and nearby requests that do not. |
| Knowledge | Approved architecture, selected dependencies, exact API references, and unresolved questions. |
| Inputs | Task packet, source locations, acceptance conditions, and required tools. |
| Decisions | What the worker may decide and what needs a project amendment. |
| Output | Reviewable deliverables, evidence, and handoff. |
| Evaluation | Realistic positive, negative, ambiguous, and unrelated cases with independent expectations. |
| Refresh | Changes that invalidate knowledge or evaluation. |

Keep AI proposals separate from user decisions. Record sources and uncertainty rather than filling gaps with assumed organizational conventions.

### The checkers

**Section disclosure (CC10-RR-001).** The reported case was
`"SOURCE-001: unable to read the section list, so no sections are cited."` passing as an
inspected absence. The cause was narrower than it looked: `_UNKNOWN` matched
"unreadable", "could not read" and "cannot read", but not **"unable to read"** — that
phrasing hit none of the alternatives, so the sentence fell through to `_ABSENCE` on its
trailing "no sections are cited". Three changes: the unknown vocabulary now covers
"unable/failed/refused to read", `_CLAUSE` splits on the comma as well (so
`"SOURCE-001 has no authoring date, while SOURCE-902 has no stable sections."` no longer
carries the section fact across to the artifact it was not written about), and
`section_absence_state()` states the precedence once — for a single artifact, an unknown
about its sections defeats an absence. That last rule is what keeps
`"…, so no sections are cited"` an unknown while leaving
`"…, and its authoring date is unknown"` a valid absence: only clauses about *sections*
are recorded at all, so an unrelated unknown never reaches the decision.

**Locator ownership (CC10-RR-002).** `WORDISH` listed the obvious filename characters and
omitted the rest, so `/other+/work/arm/a.md` and `/work/arm/a.md+backup` — two different
complete paths — matched `/work/arm/a.md` because `+` was not in the set. `PATH_CHAR`
extends the boundary. The first version of it was too wide: it included brackets,
parentheses and commas, which would have rejected `](/work/arm/a.md)` and
`/work/arm/a.md, and` — both still this file's locator. It is narrowed to characters that
would make the token a *different filename*, and the retained wrapper positives are
asserted next to the two new negatives so the tightening is visibly not blanket rejection.

**Digest association (CC10-RR-003).** In the physical decoy, a valid bare locator sits on
line 1 and line 2 reads `sha256 of /other//work/arm/a.md is <digest>`. The wrong-root
locator was correctly rejected by the form check — and rejecting it is exactly what left
its digest looking unowned, so `labelled_next_line` handed it to the valid locator above.
`OTHER_PATH`/`_between()` reject a record whose digest is introduced by a different path
standing between the locator and it. The glue there is 35 characters, read off the
fixture, so the 40-character cap does not fire: the assertion is about association, which
is the whole point of the case.

### The control path

**Preflight keys (R10-CI-001).** Entries were keyed `preflight/no-model-tests/<name>`
while `path_roots` declared no `preflight` root, so both verifiers resolved them under
`RUN/preflight/no-model-tests/` — a directory that does not exist. One convention now:
names relative to the declared root, keys `preflight/<name>`, and the root recorded in
`path_roots`, pointing at the directory GATE-INPUTS actually names.

**Selected roots (R10-CI-002).** The candidate, the delegation fixtures and the export
were three hardcoded absolute paths, read before anything verified them.
`SELECTED-ROOTS.json` declares every root and `load_selected_roots()` verifies each one —
existence, entrypoint digest, file count — *before* any query, plan or module loads. The
two this allocation does not select stay `null` and are returned as dependent blockers, so
a phase needing one fails closed instead of reaching a September 5 path. `launch()`
refuses when no authentic export exists rather than building a command against an assumed
directory.

**Scratch staging (R10-CI-003).** `build_root` copied `control/*` and `checkers/*` and
stopped, so once `freeze.CODE` grew to include `cases_r9.py` the constructor raised inside
`m.build()` before any scenario reached its predicate. `stage_selected_code()` stages
whatever `freeze.CODE` names, so the two cannot drift apart, and it reports a missing
entry by name.

**Resume lifecycle (R10-CI-004).** R10 called `main([])` then `main(["--resume"])` on one
imported module. `run_phases` builds `CTL` at import time and the pause sets
`CTL.failed`, so the second call re-entered an already-failed controller — B5 could never
be admitted, and the ordered progression the case claimed to prove was unreachable.
`_fresh_run_phases()` purges every control import and re-execs the module, so each resume
gets a reconstructed controller with the same immutable allocation and the saved evidence
still on disk. A real pause/removal scenario deletes a selected preserved archive during
the pause and requires the resumed arm to fail.

**Observation classes (R10-CI-006).** Source `runtime.phase_state`, a matching task string
and any 64 hex characters qualified both implementable classes. None of that establishes
what the class claims — an ordered checkpoint sequence is a *sequence*, and installed-
resource consultation names *which* resource. `CLASS_CONTRACT` gives each class the source
that owns it and the fields that can carry the claim; `_evidence_bytes_match` recomputes
the digest of the evidence file the record names; a missing outcome is refused rather than
defaulted to PASS. The aggregate refusal from the three deferred classes is unchanged, and
this repair does not claim that gate was ever bypassed.

**A identity and the launch seam (R10-CI-007, R10-CI-008).** `run_a_arm` derived the query
digest from the selector it was handed and compared it against that same selector, so the
wrong case, a changed query and a changed expectation all passed as unchanged. The fixed
expectation now comes from `A-CASES.json`, built from the candidate's own trigger file with
its digest recorded, and the invented `q-1` positive is replaced by the exact selected A3a
and A5a rows. The launcher is a reachable parameter, the caller is the single owner of
exclusive directory creation, and the seam receives the verified prompt bytes — local test-
interface authoring, with no native collector invented and no authority to call a model
claimed.

**Judgment consumption (R10-CI-009).** A dictionary carrying the published binding and
`outcome: PASS` satisfied a semantic gate with nobody named and none of the raw evidence.
Consumption now requires an identified reviewer from a selected authorized set, and an
evidence inventory whose paths are re-read and re-hashed. Hash and `issued_at` strings do
not establish post-output chronology; matching raw bytes that only exist after the arm ran
do.

**Emitter rejection (R10-CI-010).** The digest was length-checked only, and neither the
authority file nor the issuance record was consulted, so a stale or invented selection
agreed with itself. `selected_allocation()` now checks hex syntax, re-reads the authority
file and compares it, requires an issuance record binding the transition, and matches the
run identity.

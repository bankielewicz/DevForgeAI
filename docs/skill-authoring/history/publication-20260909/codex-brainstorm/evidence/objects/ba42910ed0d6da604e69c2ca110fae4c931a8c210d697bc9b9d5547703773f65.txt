## Runtime interface to document concisely

Root selects a devforge.brainstorm-session/v1 contract before admitting the task. It binds task/assignment identities, immutable inputs, installed resources, original deadline, mutable-output baselines and archives, checkpoint destination and external receipt destination. Mutable ledgers are not immutable inputs; preservation requires actual retained bytes. Only the protected runtime owns transitions, accepted evidence snapshots, completion and receipt publication.

The runtime supplies the current phase, fresh challenge, task identity, exact checkpoint destination and JSON shape through provider context. The worker performs the useful phase work and writes the supplied evidence shape with actual facts. Never hardcode a task ID, challenge, destination or example fact. The devforge.brainstorm-checkpoint/v1 envelope has exactly schema_version, task_id, phase, challenge, state and content. Maximum complete size is 65,536 bytes. This is observed semantic evidence, not an authoritative phase_complete flag or proof of hidden reasoning.

| Phase | Ready checkpoint content | Automatic responsibility |
| --- | --- | --- |
| Recover | known_ideas, known_decisions, missing_inputs: lists of strings, with at least one item across them | Bind current selected inputs and checkpoint before Explore. |
| Explore | ideas: 1–100 objects with unique idea_id, people, problem, outcome, alternatives, open_questions; missing_inputs list | Require the checkpoint before Record. Unknown people/problem/outcome may be null with a real open question. |
| Record | ledger_path equal to the selected idea-ledger destination | Check the persisted ledger envelope, selected identity/revision, reference revision types and required headings before Focus; the selected handoff-to-ledger binding is checked at Focus. |
| Focus | next_action, owner, completion_evidence, non_goals list, handoff_path equal to the selected handoff | Inspect all selected artifacts, complete the mechanical task and publish/read back/verify the receipt. |

The ordinary path is Recover → Explore → Record → Focus. The externally selected handoff-only path is Recover → Focus, with Explore/Record explicitly NOT_APPLICABLE. Required phase classifications come from the user's requirement to prevent skipping phases; no new per-phase human approval is introduced.

When a real blocking question remains, ask it and write state awaiting_user with content containing exactly question and blocking_dependency, both nonempty strings. The runtime preserves WAITING_USER and issues no receipt. UserPromptSubmit resumes the pending phase; it does not certify that the user adopted an idea or supplied the missing decision. Nonblocking unknowns may remain in the ordinary evidence. Each phase allows one bounded correction; exhaustion, stale/replayed evidence, deadline expiry or unavailable authority stops dependent completion. An author must not propose automatic retries or a new deadline.

Do not instruct the model to invoke delivery advance/resume/complete/check/verify or package receipt/check helpers. Root/operator commands remain operator-owned. Existing helpers are preserved as historical/resources bytes in this source allocation, not called from the managed workflow. Put substantial conditional details in the new references/managed-runtime.md and retain only the useful link and essential behavior in SKILL.md.

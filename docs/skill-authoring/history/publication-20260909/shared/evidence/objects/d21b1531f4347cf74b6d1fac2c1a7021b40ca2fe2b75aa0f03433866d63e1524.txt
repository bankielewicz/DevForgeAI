## Preserve the data and errors

- A saved document is a JSON list of objects. Every note has a nonempty string `id` unique within the list and a string `text`. An empty string is valid text. Do not trim or normalize IDs or impose a new ID format.
- A valid `[]` is an empty note list. A missing file raises `FileNotFoundError`; it is not an empty list. Empty file contents are invalid JSON, not an empty note list.
- Surface invalid JSON, decoding, read, and schema errors. Do not catch them and substitute `[]`, initialize a replacement file, or save over unreadable input. A failed load stops the dependent edit/save.
- When asked to edit one note's text, load the complete valid collection and address the note by its exact ID. Change only its `text`. Preserve all unknown JSON fields, including nested metadata, the note ID, list order, and every untouched note. Avoid reconstructing objects from only `id` and `text`.
- If the addressed ID is absent, report that fact without saving or inventing a note. If input IDs are duplicated or otherwise invalid, surface the invalid input without choosing an arbitrary match. Missing edit details prevent the write; perform useful read-only work when possible.
- Preserve the schema on any authorized write. Do not treat the existing `save` function as a validator or assume it protects a caller that bypasses a successful load. Surface write failures; do not claim a failed write left the old file intact.

## Current source facts and their limits

The selected source uses `json.loads(Path(path).read_text(encoding="utf-8"))`. `load` rejects a non-list with `ValueError("notes must be a list")`, rejects invalid note shape/types with `ValueError("invalid note")`, and rejects duplicate IDs with `ValueError("duplicate id")`. It returns the parsed objects, retaining unknown fields. No exception handler converts missing/unreadable input into an empty list.

`save` directly calls `Path(path).write_text` with `json.dumps(notes, ensure_ascii=False, indent=2) + "\n"` and UTF-8 encoding. It has no schema validation, temporary-file replacement, locking, or atomic-save guarantee. The source has no edit function. Metadata-preserving edits are an accepted requirement for callers or future authorized changes, not proof of an existing edit implementation. Preserve the current serialization convention when the requested work does not change it; metadata preservation means JSON values survive, not identical whitespace bytes.

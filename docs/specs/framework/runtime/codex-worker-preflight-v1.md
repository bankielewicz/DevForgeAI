# Restrictive native preflight

This companion implements the user's selected next step in [native readiness](codex-worker-native-readiness-v1.md), NI-T05 and NI-T07–T12. The [base contract](codex-worker-feasibility-v1.md) remains normative except for the explicit additions below. This is a nonproduction worker experiment, not an acceptance authority. Prior evidence and source fixtures remain unchanged.

## Fixed launch and bootstrap inspection

Compile one closed `restrictive-launch-policy.json` with `schema_version:1`, `policy_id:codex-0.154.0-readonly-no-external-tools-v2`, `adapter:codex-0.154.0-stdio`, and `argv`. Its SHA-256 is over exact file bytes. The vector is the retained `restrictive-launch-policy.next-proposed.json` vector from the 20260915T2118427272409Z implementation, followed by separate `-c`, `sandbox_mode="read-only"`, `-c`, `approval_policy="never"` arguments. It includes all fourteen effect-capable feature disables, both observed MCP entries, twelve plugin entries, app default and explicit app disable, OpenAI provider and ChatGPT login selection, and disabled web search. The two additional bootstrap settings match the already-required thread/turn settings. No shell, arbitrary config map, caller arguments, profile substitution, alternate home, credentials, login or operational write is admitted.

Version-matched feature review extends that vector with another 21 false overrides before the two bootstrap settings. Each uses its own `-c`, `features.<name>=false` pair, in this order: `auth_elicitation`, `code_mode_host`, `goals`, `guardian_approval`, `in_app_chat`, `in_app_dictation`, `in_app_local_automation`, `in_app_updates`, `plugin_sharing`, `prevent_idle_sleep`, `remote_plugin`, `shell_snapshot`, `skill_mcp_dependency_install`, `skill_search`, `sleep_tool`, `sqlite`, `tool_call_mcp_elicitation`, `unified_exec`, `unified_exec_tty`, `workspace_dependencies`, `worktrees`. These names are present in the retained pinned feature-list baseline. The total required false set is 35, including the original 14 (`memories`, `hooks`, `plugins`, `apps`, `browser_use`, `browser_use_external`, `browser_use_full_cdp_access`, `computer_use`, `image_generation`, `in_app_browser`, `multi_agent`, `shell_tool`, `tool_suggest`, `view_image`). Persistence/no-op flags are conservatively disabled too. A separately closed, source-reviewed allowlist covers any enabled compatibility/metadata/transport flags; an unknown enabled flag blocks qualification.

New terminal operation: `devforgeai-codex-worker-probe preflight --request <absolute-json-path>`. It accepts only the existing schema-v2 native request, exact physical executable identity, fixed policy and immutable fixture layout. It starts at most one owned app-server, performs bounded read-only protocol inspection, stops and verifies the tree, and never sends thread/start or turn/start. It is separate from WN-01/WN-02 and cannot count as either trial. Existing stdin/Ctrl+C/deadline/stream/cleanup bounds apply. A fresh run_id/run directory is required; no replay.

To remove the circular dependency between runtime observations and operator review, `preflight` validates all review identities/source completeness but permits false review findings. False means unqualified for work. `run` still requires all four findings true and independently repeats the runtime inspection in its own process before thread/start. Preflight cannot issue operator findings or protected acceptance. A positive inspection means only that its observed prerequisites passed; it does not attest the future execution or prove arbitrary sandbox workloads safe.

## Closed review v2 and source inventory

Review v2 retains every v1 field and adds required strings `launch_policy_id`, `launch_policy_sha256`, `source_inventory_ref` (absolute path), and `source_inventory_sha256`. Unknown, duplicate, missing, null or wrong-type fields fail. Both policy fields match the request and compiled record. Model/effort for these trials are exactly `gpt-6-astra`/`high`. Legacy v1 records cannot authorize this policy; peer remains v1/null profile.

The referenced inventory is produced by compiled Rust from fixed workspace, user Codex and Windows ProgramData Codex roots and the exact fixture cwd. It records paths, file hashes, directory membership and explicit absences for applicable instruction/configuration/rule/hook/plugin control inputs. It never stores file contents or reads credentials. Inventory collection has fixed size/depth/count bounds and strict reparse rejection. A referenced source absent from the inventory, source drift, new membership, unsupported runtime config origin, inaccessible path or reparse source prevents qualification. The review's `profile_sources` must exactly cover the inventory's file entries and hashes. Inventory paths are not caller-selected search scopes. Source inventory structure and limits are documented with its implementation; inventory hashes alone do not establish semantic inactivity.

Inventory is a closed object with required `schema_version:1`, absolute `fixture_cwd`, `roots`, and `entries`. `roots` requires `ancestor_root`, `workspace_root`, `user_codex_root`, `program_data_codex_root`, and `plugin_cache_root`; all must equal freshly derived roots. Each closed entry has `family` (`ancestor`, `user`, `rules`, `system`, `plugin`), absolute `path`, `state` (`file`, `absent`, `directory_index`), and optional nullable `sha256`, `bytes`, `items`. A file requires hash and byte count with no item count; a directory index requires hash and item count with no byte count; absent entries require all three null/absent. The writer emits explicit nulls. Limits are 1 MiB per file, 8 MiB total file bytes, 2,048 entries, 1,024 directory members, 32 ancestor levels and eight rule-directory levels. Verification recollects from fixed actual roots and compares complete typed inventories; a supplied inventory cannot replace search scope.

An additional terminal observation, `profile-sources --checkout-root <absolute-fixture-path>`, emits this closed inventory without starting Codex or modifying sources. It requires the native trial fixture location and original task bytes. Its stdout may be saved as source_inventory_ref. An unsuccessful collection emits a diagnostic and exit 3; invalid arguments/path use exit 2. This operation produces evidence only.

## Required pre-thread protocol

Use the retained Codex 0.154.0 schema capture. Keep initialize `experimentalApi:false`; inability to call a required endpoint blocks qualification without opting into another capability. Initialize then initialized, followed in order by:

1. `config/read {cwd:<fixture>,includeLayers:true}`. Require effective OpenAI provider, ChatGPT login, read-only sandbox, never approvals, disabled web search, required feature keys false, every configured MCP/plugin/app disabled. Validate all returned layer/origin types and referenced source identities against the complete inventory; unsupported/managed conflicts block. Retain only typed approved settings/counts, never raw layer/config payloads.
2. `configRequirements/read {}`. Null requirements means none reported; otherwise reject restrictions conflicting with this exact selection or unqualified requirements. Missing/malformed requirements cannot be treated as none.
3. `experimentalFeature/list {cursor:null,limit:100,threadId:null}`. Read all pages, maximum ten of 100 entries, reject duplicate names/cursors, invalid cursors or incomplete pagination. All 35 selected features must be present and false. Absent or null nextCursor denotes the final page as in the pinned response schemas. Unknown enabled effect-capable behavior cannot be inferred safe.
4. `hooks/list {cwds:[<fixture>]}`. Require exactly that cwd, no errors/warnings, no enabled hook. Global hooks must already be false; an empty hooks table does not replace the global switch or this check.
5. `plugin/list {cwds:[<fixture>],forceRefetch:false,marketplaceKinds:["local"]}`. No remote catalog refresh; require no load errors and no enabled plugin.
6. `app/installed {forceRefresh:false,threadId:null}`. Require all returned effective apps disabled and not callable. Catalog `app/list` is not a substitute.
7. `mcpServerStatus/list {cursor:null,limit:100,threadId:null,detail:"toolsAndAuthOnly"}` only after config proves every server disabled. Read bounded complete pages; require no running/starting/unknown server state and no tools/resources. Missing/unknown runtime state blocks when an entry is returned.
8. Existing account/read with refreshToken:false, exact Pro mode, exact selected model/effort via model/list, and rate-limit observation from the base contract. No identifiers or credentials retained.

The closed enabled-feature allowlist is: `collaboration_modes`, `compaction_image_budget`, `content_item_kinds`, `enable_request_compression`, `fast_mode`, `item_ids`, `mentions_v2`, `personality`, `remote_compaction_v2`, `resize_all_images`, `secret_auth_storage`, `steer`, `terminal_resize_reflow`, `tool_search_always_defer_mcp_tools`, `tui_app_server`, `unbounded_connection_retries`, `unified_exec_zsh_fork`. These permit compatibility, presentation, bounded first-party transport/auth and inactive execution-support behavior only; all 35 required disables still apply, and the outer dispatch deadline cannot be overridden. This is a selected conservative policy whose actual runtime behavior still requires native evidence.

For provider inspection, reject any nonempty `model_providers` mapping and any nonempty `chatgpt_base_url`, `openai_base_url`, `api_base` or `base_url` override. The captured Config schema declares model_provider while allowing additional properties; missing extra keys do not positively prove internal endpoint selection. The operator's source-bound no-custom-provider review and actual runtime observation remain necessary, with unknowns unqualified.

No inventory endpoint, empty array or feature flag alone establishes all effects inactive. Require the conjunction. Unknown/work notifications or server requests during inspection stop it. Job Object accounting must show only the one worker process has been created, including no already-exited descendants. Recheck source inventory and pinned executable identity immediately before spawn; inspect current runtime state again before a trial turn. The existing thread response must still confirm read-only/no-network/never settings before turn/start.

Use detached child console creation with the existing explicit pipe handle list and atomic Job Object attachment. A Windows console helper is not needed for stdio transport. Development diagnosis observed CREATE_NO_WINDOW creating an additional conhost.exe process; DETACHED_PROCESS preserves piped I/O while avoiding that helper. The harness itself retains its Ctrl+C handler, stdin cancellation and Job Object ownership; no breakaway or console-based worker control is introduced.

## Observations, results and qualification

Reuse durable journal event kinds. Approved inventory observations are `worker_event` records with fixed `preflight` stage and sanitized `observation`. A preflight terminal uses the existing terminal shape with null thread/turn, oracle `not_evaluated`, unchanged fixture, stopped tree, and `outcome:preflight_checked`, `reason:preflight_checked`, exit 0 only after successful inspection and cleanup. `inspect` validates this distinct outcome and cannot confuse it with a completed model turn. Error/denial/cancellation/deadline/cleanup codes otherwise retain base meanings. No all-true review or acceptance flag is generated.

Additional development checks map to existing NI groups: fixed vector/injection rejection (NI07); version/policy/inventory completeness and added/mutated sources (NI08); every effective-state validator including malformed, unknown, active and pagination paths, transient descendants and no-work trace (NI09); auth/model/effort/source/environment/sandbox denial (NI10); final identity positive observation plus existing drift rejection (NI05). Native trials remain the exact NI11/NI12 content/cancel oracles, once each, no retry. Tests of synthetic peers do not qualify native cases. All first-party source remains in executed-line coverage; both 95% floors and mandatory/security invariants remain unchanged.

If the installed profile cannot meet these predicates, preserve the concrete failed prerequisite and stop dependent native work. No configuration edits, reparse removal or policy relaxation are implied by this implementation selection. Protected framework acceptance remains separately NOT_EVALUATED.

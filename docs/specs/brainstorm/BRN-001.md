# BRN-001 — Deterministic multi-provider coding CLI with extensible guardrails and built-in SDLC skills

## 1. Context

The owner wants a terminal coding CLI that combines the strengths of Claude Code, Grok CLI and
Codex CLI. It would have guardrails built in that others can extend, and an SDLC skillset baked
in. It would run on subscription sign-ins (Codex, Grok and, per a follow-up answer, Claude) or on
local models served by Ollama, LM Studio or Unsloth. The owner says Unsloth both fine-tunes
models and serves them.

The owner confirmed four triggers:

- **Provider CLIs can't enforce rules.** Hooks and instructions can be ignored, switched off, or
  fail open, so the guardrails have to live in the harness itself.
- **Lock-in and cost.** The owner wants to switch freely between paid subscriptions and free local
  models.
- **A runtime for DevForgeAI.** The SDLC planning chain (brainstorm → PRD → architecture → epic
  → story → spec) would ship inside its own CLI instead of running as a plugin in someone
  else's.
- **A best-of-breed gap.** Each existing CLI does something well that the others don't.

"Deterministic" means both of the following:

- A code-enforced workflow: code decides the steps, gates, tool permissions and when a phase is
  done.
- Runs that are as reproducible as each provider allows.

The intended audience is the open-source public.

Constraints the owner set on 2026-09-28:

- **Language and licence.** Rust under Apache-2.0, the Codex CLI's own language and licence. A fork
  keeps the Codex NOTICE file and doesn't use the Codex or OpenAI names.
- **Operating systems.** Linux and macOS; Windows users run it through WSL.
- **Timeline.** A first prototype in about a month.

Anthropic's terms rule out Claude subscription sign-ins for third-party tools (ASM-08), so Claude
is now reached through an API key (IDEA-19), and Claude sign-in (IDEA-16) is parked.

## 3. Target users

| Persona | Job to be done | Current workaround | Pain |
|---|---|---|---|
| Solo developer with several subscriptions | Use whichever model is cheapest or strongest for the task | Switch between Claude Code, Codex CLI and Grok CLI | Duplicate config, lost context, different habits per tool (PRB-02, PRB-04) |
| Spec-driven developer | Run the planning chain with gates that actually hold | DevForgeAI skills as a plugin inside a provider CLI | The model can skip steps; hooks fail open (PRB-01, PRB-03) |
| Reviewer or auditor | Know exactly what an agent did and repeat it | Read transcripts by hand | No replay; runs differ (PRB-05) |
| Local-model user | Run the same workflow offline or for free | Ad-hoc scripts around Ollama or LM Studio | Tool calling breaks; loops stall (PRB-06) |
| Open-source adopter | Add team-specific rules and skills | Fork or patch the tool | No extension point for guardrails (PRB-07) |

## 5. Evaluation method

> Diverge-converge: problems were framed first, ideas were generated without judgment, and each
> idea was then rated high, medium or low for value, effort and risk. The score is
> 2 × value − effort − risk, counting high = 3, medium = 2 and low = 1 (range −4 to 4); a higher
> score is a stronger candidate for promotion.

The scores don't capture everything:

- **Low scores, still promoted.** IDEA-05 (score 0), IDEA-11 (0) and IDEA-16 (1) were promoted
  because they are the owner's requirements or preferred path, not because of their scores.
- **Where the risk sits.** For IDEA-05 and IDEA-16 the risk is almost all in the providers' terms
  for third-party use of subscription sign-ins (ASM-01, ASM-02, ASM-08), not in engineering.
  IDEA-15 is the ordering to fall back on if any of those checks fails.
- **Owner ideas vs. mechanisms.** IDEA-02, IDEA-03 and IDEA-04 are the product brief in the owner's
  words. IDEA-06, IDEA-07, IDEA-08, IDEA-10 and IDEA-13 are the mechanisms that make them
  concrete. Eleven of the 16 ideas were promoted in version 1, more than a typical brainstorm,
  because this one defines a whole product. Version 2 promotes 15 of 20.
- **IDEA-12.** It rates as cheap, but it leaves tool calls under the vendor CLI's control while
  they run. That is the gap in PRB-01.
- **Version 2 ideas (2026-09-28).** IDEA-17 scores only 1 because subagents, plan mode, hooks and
  plugins are real work on top of the fork; it was promoted because the owner named those features.
  IDEA-18 scores 4 because the fork already has most of it. IDEA-19 trades the subscription's cost
  advantage for staying within Anthropic's terms. IDEA-20 is low effort but risks missing upstream
  fixes, which is why changes are still taken selectively.

Web research on 2026-09-28 (sources in the frontmatter) found:

- **ASM-01, validated.** The Codex lead said on 2026-05-23 that a ChatGPT account can be used in
  other tools, and OpenAI's developer page for open-source projects names OpenCode, Cline and pi
  as fine to use. Only pooled or shared subscriptions are unsupported. No terms clause grants it,
  so OpenAI could withdraw it.
- **ASM-02, still open.** A Grok subscription sign-in exists (grok.com OAuth, used by OpenClaw and
  Warp), but access appears to be limited by tier, and xAI's current terms couldn't be read.
- **ASM-07, still open.** The licence half holds: Apache-2.0, with the NOTICE file to carry and no
  use of the Codex or OpenAI names. The cost half is in doubt: `main` had 3,602 commits and 279
  releases from 2026-06-28 to 2026-09-28, rising each month, and OpenAI accepts no outside pull
  requests. IDEA-20 is the response.
- **ASM-08, invalidated.** Anthropic's Claude Code legal page says third-party developers may not
  route requests through Free, Pro or Max plan credentials. Only the unmodified Claude Code binary
  may use them. OpenCode was blocked on 2026-01-09.
- **Unsloth.** Unsloth Studio serves an OpenAI-compatible API itself, including `/v1/chat/completions`
  and a non-stateful `/v1/responses` with tool calling, and documents Codex use. The Codex CLI
  speaks only the Responses API. It already ships Ollama (0.13.4 or newer) and LM Studio
  providers, and both serve `/v1/responses`.

## 8. Candidate success signals

- A guardrail blocks the same forbidden action under every supported provider, including when
  it is attempted through a shell subprocess.
- Replaying a recorded session reproduces its tool calls and file changes exactly, with no model
  calls.
- The DevForgeAI brainstorm skill runs unchanged in the new CLI and passes its eval suite at
  ≥ 0.8 per case.
- A user switches between a sign-in provider and a local model mid-project without editing
  configuration.
- An outside contributor adds a guardrail or a skill without forking the CLI.

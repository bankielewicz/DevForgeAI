# BRN-002 — A background color option for the Taskmaster pane

## 1. Context

Bryan asked how to add a background color option to the Taskmaster pane, the Claude Code mod that
shows each request's task list with progress bars beside the chat. At intake he said what triggered
it: the pane should signal the request's state by color. The option is for anyone who installs
Taskmaster, not only his own setup, and it should allow theme colors plus custom ones.

Today Taskmaster has one color setting, Bar color, which colors only the progress bars' fill:
Default adds no color, and its other four choices are theme keys. Besides the bars, only the
enforcement banner has color: a warning border and heading while enforcement is on, and a warning
"Blocked" line after enforcement refuses a change. The pane opens with no background of its own. Claude Code's mod API already
takes a `backgroundColor` when a pane opens (a theme key, a raw color or `"transparent"`), and a Box
inside the pane takes `backgroundColor` and `borderColor`. A pane background is a request, not a
grant: a surface with no counterpart for a theme key keeps its own look.

## 5. Evaluation method

> Diverge-converge: problems were framed first, ideas were generated without judgment, and each
> idea was then rated high, medium or low for value, effort and risk. The score is
> 2 × value − effort − risk, counting high = 3, medium = 2 and low = 1 (range −4 to 4); a higher
> score is a stronger candidate for promotion.

Value is weighed against the trigger Bryan named (signalling state, PRB-01) and the audience he
named (anyone who installs Taskmaster, PRB-02 and PRB-03). The ratings lean on assumptions nobody
has checked yet:

- IDEA-03 depends on ASM-01. Opening the pane again on every state change might move it, take
  focus or flicker, and a fill across the whole body is where unreadable text would show most. That
  is why its risk is high.
- IDEA-04 depends on ASM-02 (a band paints full width). If that fails, IDEA-09's border is the
  nearest substitute.
- IDEA-01, IDEA-03 and IDEA-06 depend on ASM-03 and ASM-05 (theme keys stay readable, and a surface
  that ignores a background stays usable).
- IDEA-02, IDEA-05 and IDEA-07 depend on ASM-04 (a raw color can be typed in). IDEA-07's contrast
  check also needs the theme's text color, which a mod may not be able to read.
- IDEA-10 signals only the moment a state changes, which is easy to miss, so its value is low.

The ideas combine. IDEA-06 is a frame: IDEA-01 and IDEA-02 fill its Fixed mode, IDEA-04 (or IDEA-03
or IDEA-09) fills its Follow state mode, and IDEA-08 is a rule about which colors each mode takes.

## 6. Convergence

Bryan accepted every proposed disposition on 2026-11-19 and confirmed that the brainstorm has
converged.

The promoted ideas form one option. A single Background setting (BRN-002#IDEA-06) has three modes:
Off, Fixed color and Follow state. Fixed color offers the theme keys, Default and Transparent
(BRN-002#IDEA-01) plus a custom raw color (BRN-002#IDEA-02), as Bryan asked at intake. Follow state
colors a full-width band behind the current request's header (BRN-002#IDEA-04). The band had the
highest score: it signals state over a small area, keeps the rest of the pane readable, and needs no
pane re-open.

Parked: a rule that state colors use theme keys only (IDEA-08), left for the PRD to settle with
custom colors; a state-colored border (IDEA-09), the fallback if the band can't paint full width;
a whole-pane state tint (IDEA-03), until re-opening the pane is shown to be safe; and a contrast
guard for custom colors (IDEA-07), since a mod may not know the theme's text color. Rejected:
per-state color settings (IDEA-05) and a brief flash on each state change (IDEA-10).

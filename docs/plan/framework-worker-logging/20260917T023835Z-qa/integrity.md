# Pre-execution test-integrity inspection

Candidate inventory: all67 files in candidate-manifest.json; 15 runtime Rust files plus the Rust integration/support modules, manifests, fixed data and supplied supplemental harness. No candidate changes. This is an integrity assessment, not exhaustive security analysis or runtime qualification.

Rust attributes were enumerated with their module context and inspected: built-in test/cfg(test)/path/repr/default/derive and serde serialization attributes; one allow(dead_code) is confined to shared test fixture API. Cargo has no first-party proc-macro crate, build script, mocking dependency, macro_rules decorator factory, cfg(coverage) exclusion, ignored test or should_panic test. Imports/re-exports resolve to std, serde/serde_json, sha2, tempfile, windows-sys, this library or inspected test modules. The test-only path modules resolve into candidate tests/support. No confirmed mock decorator or analogous mocking attribute, including unused wrappers, was found. Third-party dependency internals are outside the first-party prohibition; first-party serde derives were checked as serialization, not mocking.

Semantic review concentrated on every changed runtime logging/capture/journal/runner/process/protocol/request path, changed support/test files, fixed policy, all WF group bodies and shared process/profile/recovery/error helpers. Test syntax and assertion locators were inventoried in the inherited source/identity/effective-profile suites. Behavioral confidence additionally requires the independent cases in the plan; a locator search alone is not asserted as complete semantic proof.

Specific boundaries:
- capture::reader uses real Read and thread/channel accounting. Cursor and explicitly failing Read inputs cover the same reader function in unit tests; real Windows children remain separately required. Constants are asserted at exact/over limits; invalid UTF8 uses literal bytes.
- logging sink fault tests use actual invalid destination/read-only File handles; byte-cap testing of the private writer proves its byte cap only. It does not prove arbitrary invalid JSON is valid diagnostics.
- tests/support/query_handle.rs DuplicateHandle requests access0x0008 (job terminate) with no query access, invokes the unchanged OwnedProcess accounting -> QueryInformationJobObject call, restores the original handle even on panic, and rethrows panics. No API result interception. diagnostic_cases asserts windows_error_5, null counts, emitted/persisted agreement, stopped job and no work; this is private guard runtime evidence, not a native Codex trial.
- final_source_check_cases replaces only a private final checker to observe after-intent invocation/rejection against a real admissible peer. Its production mapping is runner::execute -> verify_before_spawn -> real review/identity/logging checks, directly inspected. It cannot alone qualify installed-profile freshness.
- WF-13/14 use actual test-held Windows process handles; WF-16 explicitly requires120..131s for the production watchdog. Subfixture assertions remain conjunctive. Library short deadlines and evidence/cleanup injection are explicit contract seams, not production input options.
- synthetic peers are separate Rust processes, validating outbound traces; immutable expected fixture data is not handed to the worker. Tests use literal negative outputs and no second-turn/no-work predicates.
- recovery/inspector tests mutate only test-owned evidence and assert read-only behavior. Existing logging inspector tests remove summaries/status/file and tamper bytes. They do not exhaust semantic capture consistency; QA-09 supplies additional negative controls.
- no confirmed result gaming has been identified. Selected tests have nonconstant product assertions; fixture construction and compiler/list/help outcomes receive no behavioral PASS credit. Unverified semantic regions remain bounded by later independent oracles; no assumption that green developer summaries qualify the candidate.

QA-owned bind_inputs.py and run_command.py were read back before use. They collect exact hashes, reject drift, use subprocess argument vectors/no shell, create exclusive attempt paths, preserve nonzero exits/raw streams, and refuse commands if STOP.json exists. No result fabrication, silent retry, dependency installation or denominator reduction. Every new QA helper will receive its own readback/inspection before execution.

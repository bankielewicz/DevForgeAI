# Validator standards and behavioral evaluation enhancement

The approved plan selects development maintenance under `src/agents/skills/skill-validator` using skill-creator. Operational copies, previous evidence and legacy record meanings remain unchanged. This document selects supporting Python evidence utilities, not Rust framework authority. The baseline contracts are [validator specification](../plan/skill-validator-spec.md) and [adaptive extension](../plan/skill-validator-adaptive-enhancement-spec.md); this extension changes only the obligations below.

## Requirements and interfaces

- **SVE-01 Standards:** bind the eight supplied `docs/Agentskills` documents by raw-byte digest and source locator to a catalog identifying mandatory format, host compatibility, advisory, semantic and host-implementation-only material. Preserve format/host/project separation. Do not elevate optional directories, size recommendations, or checker restrictions into universal defects.
- **SVE-02 Metadata:** share checks for nonempty name/description, supported naming and lengths, optional field types/lengths, metadata string mappings and duplicate YAML keys. Malformed/unhashable/non-string keys produce located diagnostics rather than crashes. Preserve legacy observation field shapes. Unknown extensions remain unresolved applicability; selected ASCII naming is a Codex-compatible profile, not an exhaustive Unicode assertion. Agent Skills allowed-tools is a string; retain any legacy list parsing only as an explicitly limited compatibility observation.
- **SVE-03 Resources:** retain existing bounded Unicode/link/anchor/placeholder/resource observations and semantic adjudication. Emit depth/cycle/size advisory measurements. Do not execute target files during discovery or equate a declared consumer with observed loading.
- **SVE-04 Trial plan:** add `scripts/trial_runner.py` with `seal`, `run`, `check` and `summary` commands. A `trial-plan-v1` names case ID, kind (`native` or `utility`), argv, absolute cwd/write root, input digest references, prompt reference or null, independently defined expected output assertions, requirement IDs, dependencies and optional positive finite timeout. Plans and evaluator assertions stay outside the disposable write root. Protected fixture candidate/input references may point inside it and must remain unchanged. `seal` creates a new immutable attempt directory with a captured plan and input identities; `run` accepts only that directory. Each real attempt is unique. Output paths are relative to the permitted write root. Fixture candidates/specifications included in inputs must remain unchanged.
- **SVE-05 Execution:** utilities default to 120 seconds; native sessions to 600 seconds. Explicit selected ceilings override defaults. Runner launches argv without shell interpolation, sends only selected prompt bytes on stdin, captures streams directly to files, and records wall time, exit/timeout, owned process identity, input drift and artifacts. Windows execution uses an owned Job Object and a gated worker so target execution starts only after process-tree ownership is established. Job cleanup is observed, not assumed. Other platforms return NOT_RUN; never route this Windows qualification through WSL.
- **SVE-06 Recovery:** save start and final receipts separately. Missing final receipt means interrupted/unresolved; reject replay of that attempt. Check plan/original-input hashes before launch and after completion. Cleanup/drift failures block dependent work; a local timeout does not forbid independent cases. No automatic retries, timeout increases, installation, credential changes or sandbox bypass. A prior failure is never replaced by a later attempt.
- **SVE-07 Output evidence:** code graders check only declared mechanical assertions: file existence, exact UTF-8 text, or parsed JSON equality. Required unresolved semantic assertions remain NOT_RUN for separate adjudication. Zero exit or completion prose alone cannot pass a required output obligation. All observations identify requirement, case, evidence and limits. Records reject changed plan/input/output/stream bytes and plan-after-launch attempts. Summary validates a complete selected-case inventory, dependencies and unique attempts; FAIL precedes INCOMPLETE, which precedes PASS. Controls and evaluator self-tests never count as native skill scenarios.
- **SVE-08 Independent behavior:** native actors receive only skill, realistic request, raw inputs and authorized scope. Freeze expectations before scored launches. Keep exploratory trials separate. Use independent positive/adverse workflow and routing cases; implicit discovery and description classification remain separate. Optional matched baseline comparisons use equal selected budgets/inputs/model, separate workspaces and blind qualitative review where practical. Record elapsed time and only available usage measurements; no automatic comparisons or source repair.
- **SVE-09 Workflow:** instructions route relevant checks and reusable runner, show actual delivery/completion ahead of narrow structural success, require plan-before-launch and continue ready independent work until completed or genuinely blocked. Preserve manual repair handoff and Rust authority boundaries. Script smoke tests apply only to inspected declared CLI interfaces and use invalid args/closed stdin/output/exit/side-effect observations.
- **SVE-10 Qualification:** retain red/green/refactor/QA evidence, independent cases, Python JSONL results, expected results, schema, runtime information and artifact bindings. Required Windows scenarios cover metadata boundaries; quoted placeholders/Unicode/resources; stale/missing plans; process timeout/descendants; interruption/drift; blocked and independent cases; missing output despite exit zero; and completed realistic forward workflows. A real >120-second utility process with a selected native budget verifies ceiling behavior separately from model execution. >=95% line coverage and required-case pass floors apply; disclose full existing package coverage and failures, plus changed-module coverage, without denominator manipulation. Linux native and protected framework acceptance remain NOT_RUN/NOT_EVALUATED.

## Ownership, compatibility and acceptance

The runner is optional reusable evaluation support; it does not authorize effects or replace host permissions. JSON schemas describe the new supplemental family and are not added to legacy schema-1 directories. Existing command names and evidence readers remain supported. No evaluator result can authorize a framework mutation.

Acceptance requires independently observed behavior for every selected obligation, not just a source map. Missing tooling/timeout is incomplete coverage, never a source defect by itself. Changes after evaluation invalidate current-byte qualification. The QA skill's historical 42-scenario campaign is not selected for replay by this implementation.

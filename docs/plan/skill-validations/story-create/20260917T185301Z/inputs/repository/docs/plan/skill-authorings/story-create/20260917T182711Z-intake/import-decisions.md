## Source accounting and evaluation ownership

`source-manifest.json` inventories every included source file with bytes and SHA-256. `source-dispositions.json` records every disposition, destination and observed textual consumer. The one backup is excluded before content reads. No excluded CLI implementation is opened or ported. Historical migration scripts, validator scripts, fixtures, old-format samples, command templates and phase-cache schemas remain captured evidence rather than executable target resources. Their substantive output requirements are represented in the new story contract, domain references and delivery obligations; historical validator bug workarounds are not new product rules.

This is the explicitly requested skill-builder import, not a request to execute skill-validator. The installed builder requires separate assessment and prohibits generated campaigns during authoring. The repository likewise preserves authoring/evaluation ownership. The mandatory Python JSONL runner, deterministic graders, independent fixtures, expected results, schema, runtime/dependency information and digest bindings remain required external evaluator artifacts before evaluated-build completion. No structural checker, test suite, sample generated-helper execution or native trial is claimed here. Input capture, write safeguards, source searches and readback are authoring evidence only.

No new runtime algorithm is authored: the sole Python runtime helper is copied unchanged from the installed builder template. Runtime helper qualification, story generation behavior, activation/near-miss behavior, Windows/Linux support and downstream consumer trials are unperformed obligations for the manual validator request. Framework acceptance is not evaluated.

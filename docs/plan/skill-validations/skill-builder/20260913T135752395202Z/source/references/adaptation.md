# Project adaptation modes

Use `propose` for a project assessment and recommended responsibilities, `author_set` for explicitly selected proposal members, and `review_updates` for selected variants against supplied changed core/evidence. Existing single-skill creation, import, edit and adoption still use their original contracts. A role is a skill responsibility, not a native agent persona, principal, or background worker.

## Proposal and discovery

Resolve the selected project, applicable instructions and development destination. A supplied destination answers the location question. Inspect actual shell, Python 3.10+, PyYAML where existing helpers need it, and available CLI version/help before constructing commands. Do not install tools, execute configuration files, initialize Git or invoke project tests/scripts to discover facts. Commands in capability records are descriptions, never automatically executed shell strings. No GUI, browser, MCP, plugin or external service is required. Missing essential custody capabilities block dependent authoring; independent prose proposal work may continue. Actual required Rust gate enforcement is unavailable under this contract: record the missing capability, rather than a pretend command. A selected design-only output can proceed if it requires no enforcement.

Enumerate each directory before descending. Select root instructions/manifests, relevant documentation, and source/test areas needed for architecture, domain boundaries, requirements, language/toolchain, development style, testing/build conventions, security constraints and existing coverage. Separately bound explicitly selected core packages and any operational skill inventory. Exclude `.git`, `node_modules`, `.venv`, `venv`, `target`, `dist`, `build`, `__pycache__`, backups, `devforgeai_cli`, private keys, `.env` files and operational binding contents before reading/hashing. Do not follow links/junctions or special files. Additional repository exclusions apply. Secret values are never copied to excerpts; retain only a sanitized exclusion reason/path.

Capture at most 2,000 regular original files / 32 MiB aggregate across project evidence and selected cores; shared originals count once. Enumerate and total before copying, with stable-read checks. Exceeding either ceiling yields `DISCOVERY_LIMIT`, lists uninspected roots, and requires narrower scope or an explicitly changed ceiling. Do not silently truncate, split a complete claim or raise limits. Missing facts are unknown; a manifest declares intent, not installed availability. Preserve conflicting historical documents and current corrections as separate captured inputs.

Allocate a new UTC `YYYYMMDDTHHMMSSffffffZ` run under `<project>/docs/plan/skill-adaptations/`, retrying timestamp allocation only on a collision. Store exact relevant inputs in `inputs/`, then author `project-evidence.json`, `adaptation-proposal.json` and `adaptation-report.md` using the [closed contracts](adaptive-contracts.md). Fact locators cite saved UTF-8 passages with actual supporting content. Preserve source path/digest associations in the report so resume can compare originals, not merely unchanged snapshots. Do not capture concrete project identity in this run.

For each responsibility, identify unmet requirements or justified specialization. Retain a verified existing skill when it already covers the need; do not manufacture duplicate experts. Product-specific expertise needs observed domain/architecture facts or explicit domain requirements, with precise ownership, exclusions, inputs, outputs, effects, recovery and handoffs. Preserve project conventions: Python/TDD, implementation-first Rust, service-local TypeScript workspaces and documentation-only work may require different outputs. Ambiguous same-scope conventions become a gap; do not invent a uniform toolchain or ceremony.

Variants have distinct names/destinations and complete parent dispositions. A core edit is a separately selected ordinary edit. Record requirements, fact IDs, member dependencies, required capabilities and directed handoffs. Required consumers depend on their producers. Graphs are acyclic. A JSON artifact handoff binds a retained local schema; text/file sets define observable fields/content. `NO_CHANGE` means all members retained with no material gaps; `BLOCKED` means material gaps prevent a complete recommendation; otherwise `PROPOSED`. A blocked proposal can retain independent actionable members.

Run `python -B -X utf8 <builder>/scripts/adaptive.py inspect --record <proposal>` as a read-only input-custody observation. Shape or references being valid does not establish grounding, authorization or quality; inspect cited support yourself. Return the report and exact proposal reference. Proposal alone generates no skills.

## Sequential selected-set authoring

Retain `adaptation-selection-v1` before candidates in a fresh `<project>/docs/plan/skill-set-authorings/<run-id>/`. It binds proposal, exact member IDs, one destination each, captured current authorization, and permitted effects. Reuse explicit authorization already supplied; no second approval for the same resolved member. Material new choices remain unresolved. Do not automatically add dependencies: selection must include every prerequisite, including explicitly retained verified members.

Before authoring, compare original project/core evidence with captured identities, resolve known history using [regeneration.md](regeneration.md), and run `adaptive.py plan-set --selection <selection>`. Validate all selected destinations/overlaps, inputs and available essential capabilities. Keep immutable pre-edit existing/parent PackageRefs against captured packages (preserve their name directories); live destinations are separate. The helper's ASCII-ID topological order is the execution order. Invalid selection shape, cycles, unknown membership or stale shared inputs stop dependent work. A member-local prerequisite failure blocks that member and its dependents; retain the original selection and continue independently verified members in its topological order. Record the failed helper observation and the precise per-member prerequisite, rather than relabeling the observation VALID or silently narrowing full-set membership. A later explicitly changed selection gets its own immutable record.

For each member in order:

1. If a prerequisite is BLOCKED/PARTIAL/DEPENDENCY_BLOCKED, record DEPENDENCY_BLOCKED with the failed prerequisite and no member execution. Continue independent members.
2. A retained member requires exact current package verification; record RETAINED without fabricated authoring history. Otherwise prepare its existing `authoring-contract-v1`, embedding adaptive Requirement rows in `requirements` and retained proposal/selection inputs in `inputs`. No extra legacy top-level fields. Capture its history and authorized managed paths. All captures and per-member runs remain disjoint from destinations.
3. Use existing `authoring.py begin` and `publish` with per-member runs in `<project>/docs/plan/skill-authorings/<name>/<run-id>/`. Author the descriptor, linked contract, copied generic helper and essential runtime check instructions from the linked resources. Preserve B/C/N protection, core bytes, user edits and unrelated resources. Recheck inputs and changed paths before writes and read back afterward.
4. Record AUTHORED only with actual complete publication/readback, PARTIAL with every applied path if effects occurred before failure, otherwise BLOCKED. Retain every attempt. No rollback of successful members, failed-baseline advancement, test execution, validator calls or automatic repair cycle.

Author `set-authoring-v1` referencing actual per-member authoring records, requests and completed package manifests. Reduction: all RETAINED is NO_CHANGE; at least one AUTHORED and others AUTHORED/RETAINED is AUTHORED; delivered changes plus unresolved members is PARTIAL; otherwise BLOCKED. Retention alone is no authored change. Both quality statuses remain NOT_PERFORMED.

Publish a manual `set-validation-request-v1` only when a nonempty dependency-closed eligible set exists. Eligible members are AUTHORED/RETAINED with complete current bindings. `full_set` contains exactly the entire selection with empty omission arrays. Otherwise `eligible_subset` explicitly partitions the original selection into requested and omitted IDs with at least one omission. Include precisely the proposal handoffs with requested endpoints; list all remaining selected-set handoffs as omitted. Handoffs outside the selection are not assessed. If there is no eligible subset, publish no request and list the unavailable members. State that the request grants no external effects. Keep the immutable selection reference; a subset never claims full-set coverage.

Use `adaptive.py inspect` on final envelopes, then return exact destinations, paths, input/package digests, actual history/results, omissions and the manual request. Stop at development source. Direct single-skill manual requests need no envelope.

## Selected update review

Require selected existing variants, retained exact parent references and explicit current core/project inputs. No registry, polling, network update selection or automatic rebase. Compare recorded parent digest with current core bytes, then requirement statements and relevant project evidence. A changed digest establishes input change, not a defect. Map affected responsibilities, tests specified by the contract, resource routes and handoffs; record semantic-equivalent changes as such. `NO_CHANGE` requires relevant bytes and requirements unchanged.

Write a fresh impact proposal with `mode: review_updates` and `prior_proposal` when available. For this mode the unchanged-input rule takes precedence over the proposal's all-retained shortcut: equivalent semantics with changed bytes produces PROPOSED with retained members and an explicit input-change explanation. Missing parent bytes, unresolved identity, absent full requirement mapping, stale evidence or contradictions are concrete gaps; never reconstruct a successful parent history from current files or a missing convenient pointer. Without sufficient historical evidence, do not claim NO_CHANGE. Preserve old snapshots and results. A later current selection may authorize variant revision under normal custody, not core edits or reuse of old quality results.

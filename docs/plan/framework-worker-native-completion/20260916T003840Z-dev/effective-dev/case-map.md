# Declared effective-profile edge cases

The required-case denominator for this focused slice is **8 Rust test functions**. Each function is counted once; multiple assertions are subfixtures and do not inflate the denominator. Expected results come from DFF-WORKER-PREFLIGHT-01's closed effective-state rules, source binding, pagination limits and typed projection requirements.

| ID | Requirement-derived behavior | Independent expected result |
| --- | --- | --- |
| EP-EDGE-01 | Effective configuration accepts only reviewed disk sources plus one exact session-flags layer; project config must contain the fixture cwd. | Reviewed packaged/system/legacy/user/project layers qualify and produce only fixed counts/settings; unreviewed, profiled-user, escaping project, managed/unknown, empty/oversized-layer, missing/duplicate-session cases fail closed. |
| EP-EDGE-02 | Custom provider or endpoint state is forbidden; the session layer is a closed exact policy projection. | Null/empty provider and endpoint values remain inert; nonempty or malformed values, missing/extra closed keys and active/malformed app/MCP/plugin values fail with typed errors. |
| EP-EDGE-03 | Feature pages must be bounded, complete, unique and closed to the pinned required-disable set; only the contract's allowlisted enabled compatibility flags may be enabled. | A complete page containing the 35 disabled requirements plus all 17 allowlisted enabled flags qualifies with exact counts; missing/duplicate/invalid/oversized/cursor/unknown-enabled inputs fail closed. |
| EP-EDGE-04 | Hooks inspection permits only disabled, well-typed supported hook records and journals counts only. | Disabled records covering every supported event/source/trust/handler shape qualify without retaining commands, paths, server/tool names or hashes; duplicates, enabled or malformed records fail closed. |
| EP-EDGE-05 | Local plugin inspection requires no load errors, unique disabled plugin IDs, bounded inventories and supported source/policy shapes. | Disabled local/git/npm/remote plugins qualify with exact installed/count projection and no input secrets; load errors, duplicates, enabled entries, malformed policies/sources/path or bounds violations fail closed. |
| EP-EDGE-06 | Installed apps must be unique, disabled and non-callable, with bounded typed metadata. | Missing/null/string runtime names qualify and project counts only; duplicate, enabled, callable, malformed runtime or oversized inventories fail closed. |
| EP-EDGE-07 | MCP status pagination requires unique disabled servers, supported auth states, empty tools/resources/templates and no tool error. | Supported inactive states qualify with exact counts; active/duplicate/malformed/pagination/oversize/tool/resource/template/error cases fail closed. |
| EP-EDGE-08 | Requirements and all public validators distinguish unqualified observations from malformed protocol shapes while retaining no raw payload. | Explicit null requirements qualifies; present requirements are `profile_unqualified`; missing/wrong container types and malformed public-validator roots are `protocol_error`.

Focused execution is `cargo test --locked --offline --test effective_profile_edges`. Formatting and Clippy may be run for the owned file/target after the focused tests. Full-suite pass rate and full-source coverage are measured later by the root development campaign, then independently by QA.

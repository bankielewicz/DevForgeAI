# Independent production predicate comparison

Comparison inputs are the actual baseline-snapshot and current original files, verified against their manifests. independent-baseline.diff was regenerated in this QA root; changed-files.json identifies exactly eleven changes (five existing production files plus new diagnostic.rs, three existing test/helper files plus new diagnostic_cases.rs, and README).

| Production change | Independent comparison and implication |
|---|---|
| diagnostic.rs (new) | Closed enums for source boundaries, RPC stages/checkpoints/categories, config sections/predicates; numeric Option<u32> counts. No caller-provided string/value is carried by Diagnostic. RpcPredicate maps only fixed reasons, with cause-neutral other_rpc_failure fallback. Nothing reads diagnostics to admit or dispatch work. |
| effective_profile.rs | fixed_config adds only category assignments and extends the five constant setting tuples with categories. Existing values, equality/type checks, short-circuit order and exact-key checks remain. validate_config becomes a compatibility adapter around the same inner traversal; the inner logic adds section/predicate assignments before existing checks. All origin values, covered normalized paths, layer sources, bounds and exactly-one-session check retain original order and errors. Success JSON has unchanged fields/values. |
| process_windows.rs | only_worker_started obtains the same TotalProcesses and ActiveProcesses from one accounting() invocation through process_counts. That accessor returns the tuple from the same JOBOBJECT_BASIC_ACCOUNTING_INFORMATION; it never independently queries two snapshots. Predicate remains total==1 && active==1. Exited children still contribute to TotalProcesses. Spawn/job/pipe/control/stop/drop code is unchanged. |
| protocol.rs | New source_review records only on actual closure error and returns that original result unless evidence recording itself fails. New process_guard calls process_counts exactly once, emits observed initialize/config samples or denials, then propagates the original query error or profile_unqualified for non-1/1. QueryFailed carries both counts None. rpc wraps the existing rpc_inner, retains original return/error, and emits closed category only for failed observed preflight RPCs. Existing before-send/after-receive/final process checks remain in place. Config preflight replaces profile_observation only to record the first validator failure; profile_rpc mapping and success record are unchanged. Dispatch still verifies source before preflight and all-true review after preflight before thread/start. |
| runner.rs | Only existing post-spawn/preflight and post-preflight review calls are wrapped. Public run/preflight still call execute with the correct mode; execute still chooses the compiled final verifier. No new caller seam. Final identity check remains immediately before spawn without intervening emit callback. All-false is permitted only for inspection. |
| lib.rs | Exports diagnostic module only; no dispatch policy change. |

Byte-identical against baseline: Cargo.toml/lock, launch_policy.rs and restrictive-launch-policy.json, native_identity.rs and native-executable-identity.json, profile_sources.rs and plugin-source-identity.json, request.rs, main.rs, journal.rs, oracle.rs and original fixture identities. Fixed argv, adapter/model/effort/policy/review formats, source/executable checks, one-server/thread/turn and no retry limits are unchanged. The original deadlines, cancellation, cleanup precedence and terminal mapping were reviewed around the changed call sites; diagnostic writes use existing Journal::append and propagate failures through ?. No Python helper makes a runtime acceptance decision.

Query failure feasibility: normal API calls hold a valid private OwnedHandle and expose no public accounting-error injection. Closing a live handle behind Rust ownership, modifying production memory by guessed layout, or changing the product would be unsuitable. The declared test wrapper can instead legally duplicate the owned job with JOB_OBJECT_TERMINATE and without JOB_OBJECT_QUERY, exchange only the owned synthetic process handle, execute the original accounting code, restore the original handle and verify actual cleanup. Runtime outcome remains unproven until QI01/QI02 execute. Wrapper-specific CARGO_MANIFEST_DIR roots are deliberately not qualified by those tests; original package tests retain path-sensitive admission/CLI coverage.

This comparison supports observation-only intent; runtime, privacy and no-work conclusions depend on independent tests and the inherited campaign. No whole-run stop trigger was established by this static review.

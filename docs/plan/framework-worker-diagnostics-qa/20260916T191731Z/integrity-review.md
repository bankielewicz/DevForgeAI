# Pre-execution integrity review

Scope: all 58 manifest files, including 47 Rust source/test/helper files enumerated in syntax-inventory.json; the independent harness and intake/prepare/record scripts. This is an offline source assessment, not runtime or protected acceptance.

The Rust attribute/import inventory was resolved against actual Cargo.toml, source imports and module paths. Attributes are ordinary built-in test/cfg/path/repr/derive and serde serialization attributes. Standard derives and serde derive resolve to the pinned dependencies. No first-party mock-generating attribute/decorator, alias, wrapper or dynamic factory was found. No ignored/should_panic/coverage-off tests, optional package features, runtime-generated tests or custom test macros were found. The shared fixture module's allow(dead_code) suppresses unused helper warnings, not coverage or test execution. Searches served as locators; actual declarations, module imports, test helpers and call sites were inspected.

The source inventory has 133 #[test] functions, matching the supplied inventory: 40 library units and 93 integration tests. Assertions and branch tables establish error categories, bytes, journal contents, received RPCs and real process state. Table subfixtures are conjunctive loops; no skip is credited, no retry loop converts failures to passes, and panic/unwrap/setup errors fail the test. Setup routines are not separate product acceptance cases.

Special boundaries reviewed:

- tests/support/mod.rs creates disjoint actual files, hashes the built peer and validates requests. Retained fixtures use WF_TEST_EVIDENCE. Some basic tests use disposable TempDir directly; their raw outcomes remain in the suite log.
- peer.rs, profile_peer.rs and protocol_edges_peer.rs are deterministic external protocol stimuli. They feed the actual process/protocol/runner code, including malformed messages, blocking pipes and real descendants. Expected JSON fixtures are synthetic data; no peer result is native Codex evidence.
- console_driver.rs creates a hidden independent console and sends actual CTRL_C_EVENT. crash_driver.rs exits at the observed event, with panic if unreachable. Process tests hold real synchronization handles, check job emptiness, preserve outside sentinels and run the 120-second watchdog. F-01 full-pipe tests check deadline/control completion and both descendant handles; F-02 tests inspect actual stdout/stderr/journal bytes for sentinels.
- Identity/source tests create real owned files, junctions and symlinks. Cleanup removes only tracked links, not targets. Literal tag/hash/membership oracles are distinct from the production resolver. Private root/mapping constructors are fixture injection, not evidence of the installed roots.
- request::verify_review_v2_with injects inventory verification for review-shape units. That proves review binding/all-false behavior only. Actual source collection is covered separately, and public request/runner wiring is reviewed. Likewise runner::execute_with_final_check's synthetic closure proves placement after durable spawn intent, not installed-profile validation.
- preflight_recovery.rs constructs journal records to test read-only inspection and corrupts them for rejection checks. These are inspector inputs, not claims that a native preflight ran.
- Native admission tests read the pinned executable identity but use invalid policy/review and assert no spawn. Synthetic CLI source cases select test user/system roots; the runtime rejection cases with inherited environment reject invalid layout/fixture before collection.
- Native qualification WN-01/WN-02 and protected framework acceptance receive no credit from any fixture.

New QA helpers: no mock attributes or replacement product implementation. The private wrapper includes original files; qa_without_query uses a real duplicate handle with reduced access, retains the original OwnedHandle, restores it after normal return or unwind, and resumes any panic. It neither intercepts QueryInformationJobObject nor hardcodes its return. All expected errors/events are assertions against actual outcomes. Fixture policy constants were transcribed independently from the selected contract; config tests call the original dependency's public validators. The peer intentionally rejects the requirements RPC after a valid config response, so the config-success test does not claim complete preflight success. Canaries are retained as stimulus but must be absent from product journal/output. The negative-control contamination must be rejected by the same comparison predicates. QI07 checks both wrapper and original dependency public review methods.

Python helpers only record exact bytes, unique inventories, subprocess exit/streams and identity checks. They do not emit framework acceptance, waive cases, hide nonzero status, repeat failed cases or alter candidate files. The recorder starts one command and returns for assessment; no next campaign is launched automatically. Review result: **no confirmed integrity failure found**; no unresolved dynamic decorator mechanism identified. This finding does not supply test passes or line coverage. Reinspect any changed QA helper before use and assess resulting evidence for hidden failures.

# ADR-001 — Mandated identity authority

## Context

[PRD-001](../prd/PRD-001.md) explicitly requests an identity-provider ADR for
FR-001. Personal Google accounts are required by NFR-004, while
[POL-001#SET-01](../policy/POL-001.md) mandates Org A Identity Platform (OIDC)
without a product override. NFR-001 requires administrator revocation of signed-in
sessions to take effect within five minutes. The referenced organization ADR-104
and platform documentation are absent.

## Decision direction

The product's identity authority is fixed by policy: Org A Identity Platform.
Propose personal Google federation through that authority, with backend-mediated
OIDC and authoritative application session checks as specified in
[ARCH-001](../architecture/ARCH-001.md). The product does not authenticate Google
credentials directly or maintain a password store. Application session enforcement
must integrate with the organization's contract rather than create a second
identity authority.

Platform choice is constrained; federation capability and revocation integration
are unresolved. This ADR remains proposed and blocked for implementation by
ARCH-001 gate G-01. Empty `blocked_by` metadata means no blocking document ID has
been supplied; it does not mean this decision is ready. No acceptance or external
architecture-board approval is claimed.

## Alternatives

| Alternative | Disposition |
|---|---|
| Direct Google OIDC from the product | Meets the credential constraint but violates SET-01; not eligible under current policy. |
| Org A identity with personal Google federation | Only identified route compatible with both constraints; capability and revocation evidence required. |
| Org A identity requiring organization-issued accounts | Fails NFR-004 unless the approved PRD changes; not an acceptable silent substitution. |
| Custom credentials or another identity vendor | Violates the mandated platform and adds unsupported scope. |

## Consequences and validation

Platform outage blocks new sign-ins. App sessions require shared revocation
state, fail-closed authorization, and tests across all deployed instances. A
stateless long-lived token accepted without a revocation check is insufficient.
Do not assume provider logout revokes application sessions, or that revoking an
application cookie revokes provider refresh/session state.

Close G-01 with the platform contract and a demonstrated Google federation and
revocation flow, including reauthentication and concurrent requests. The exact
300-second maximum remains unchanged. FR-001, NFR-001, and NFR-004 remain blocked;
booking and roster inherit the dependency. Compliance/accessibility gates in
ARCH-001 apply as well. If federation cannot satisfy both constraints, escalate
the documented conflict to the authorized requirement/policy owners; this ADR
does not grant an exception.

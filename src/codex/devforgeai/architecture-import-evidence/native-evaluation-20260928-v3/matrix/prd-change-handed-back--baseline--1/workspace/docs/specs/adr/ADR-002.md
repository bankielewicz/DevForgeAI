# ADR-002 — Hosted transactional application

## Context and decision

[PRD-001](../prd/PRD-001.md) describes 120 volunteers, three shifts a day, mobile
web access, a daily coordinator roster, and no on-site server. Propose a single
hosted web/backend deployment with logical modules and a managed relational
database. All protected data crosses backend authorization. A database transaction
and uniqueness constraint enforce booking capacity and prevent duplicates;
coordinator-only projections enforce phone privacy. Detailed flows and data
boundaries are in [ARCH-001](../architecture/ARCH-001.md).

## Alternatives and consequences

| Alternative | Assessment |
|---|---|
| Hosted modular application and relational database | Proposed: one transaction boundary and one authorization boundary; small operational footprint for the pilot. |
| Separate booking, identity-adapter, and roster services | No stated independent scale or deployment need; adds distributed consistency and operations work. |
| Client-side database access with client-side filtering | Does not provide the required trusted authorization boundary for contact data or booking invariants. |
| On-site deployment | Ineligible under NFR-003. |

The backend and database remain operational dependencies. Availability and recovery
targets need approved criteria; managed hosting alone proves neither. Protect
database access, secrets, logs, backups, and restore paths. A provider and runtime
are not selected until organizational control requirements are known. No new
vendor purchase or hosting deployment is authorized by this document.

## Validation and readiness

Draft epics can use the structure now. Before implementation readiness, close
ARCH-001 G-02/G-03 for compliance and accessibility; close G-04 for operating
definitions and G-05 for roster freshness where applicable. Authentication depends
on [ADR-001](ADR-001.md). This ADR is proposed, not approved. Verify concurrent
last-slot booking, duplicate retries, daily boundaries, authorization and field
exposure, hosted deployment inventory, and backup restore against the actual
implementation. Those tests have not been run in this documentation-only workspace.

# ADR-004 — Restrict volunteer phone data to coordinator-authorized reads

## Context and proposed decision

NFR-002 says phone numbers are visible only to the coordinator. Enforce this at the
server, not by hiding a UI field. Keep contact records separate from volunteer identity,
shift and booking records. Only a coordinator-authorized roster/contact operation may
load and return phone numbers. Response schemas explicitly allow fields; general
serialization of storage objects is prohibited.

| Actor/capability | Book own shift | Read daily roster and phone | Revoke volunteer sessions |
|---|---|---|---|
| Anonymous | No | No | No |
| Volunteer | Yes | No | No |
| Coordinator | Only if also a volunteer | Yes | Only if also an administrator |
| Administrator | Only if also a volunteer | Only if also a coordinator | Yes |

Read roles from trusted application state on each request; client input and editable
identity metadata cannot grant roles. A volunteer cannot read their own stored phone
number through this application either: the PRD supplies no self-access exception.
Provisioning roles is an audited operator procedure, not a public role-management API.

Do not copy phones to the identity provider, session claims, URLs, ordinary volunteer
responses, analytics, error messages or logs. Disable request/response body logging and
redact sensitive fields before emitting structured events. Authenticated responses use
`Cache-Control: no-store`; no service-worker/offline cache contains rosters. Clear roster
state on logout or authorization failure. Audit contact access using actor/subject IDs
without the contact value. Apply the same restrictions to exports and support tooling;
neither is part of this pilot.

Hosted storage/backups are encrypted and restricted to service identities. Application
administrators do not receive database/backup access. The coordinator provisions contact
data through a coordinator-authenticated import procedure; no new collection form is assumed. Cloud
privileged access can still bypass application controls: A-04 explicitly holds the
scope of “only the coordinator” open before declaring NFR-002 ready. Do not claim this
proposal protects plaintext from a cloud-account owner with unrestricted control.

## Alternatives and consequences

UI-only hiding exposes the value in network responses. A shared profile payload creates
accidental disclosure paths. Separate storage and response schemas add explicit joins
and permission checks but make access testable. Administrator does not imply coordinator.

## Confirmation evidence required

Test the entire role matrix, including a volunteer requesting their own and another
volunteer's contact record, an administrator without coordinator rights, forged roles,
removed roles, caches, browser storage, error paths and logs. Inject a distinctive phone
value and search captured unauthorized responses and telemetry for it. Confirm authorized
coordinator access and documented backup/operator permissions. These checks are not run.

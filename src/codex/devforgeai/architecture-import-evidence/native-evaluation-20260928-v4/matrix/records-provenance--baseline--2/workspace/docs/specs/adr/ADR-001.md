# ADR-001 — Identity provider and sign-in method

## Context

[PRD-001](../prd/PRD-001.md) explicitly requires an identity-provider ADR for FR-001.
Volunteers use mobile browsers; the product must be hosted, prevent phone disclosure
to anyone except the coordinator, and allow administrator session revocation within
five minutes. No existing identity tenant, volunteer email availability, provider
budget, provisioning policy, or recovery method is supplied.

## Decision status

**Proposed; provider and sign-in method unresolved.** Prefer a hosted identity service
behind the adapter in [ADD-001](../add/ADD-001.md). Keep application sessions and
authorization under application control. No vendor has been selected, researched,
purchased, configured, or represented as approved.

## Options and tradeoffs

| Option | Advantages | Unresolved fit / cost |
|---|---|---|
| Existing organization-managed identity service | Could reuse account administration and support processes. | Existence is unknown; volunteer eligibility and mobile access must be established. |
| Dedicated hosted volunteer identity service | Separates volunteer accounts from staff systems and avoids operating credential infrastructure. | Must establish supported sign-in/recovery method, account mapping, ongoing cost, and operator ownership. |
| Credentials implemented in the application | Full control of the account experience. | Adds password storage, recovery, abuse prevention, and support burden. Do not adopt without evidence that hosted options cannot meet the pilot needs. |

These are architectural alternatives, not verified claims about named services.
The smartphone assumption does not establish that volunteers possess email accounts
or can use a particular authentication method. Do not assume phone-based sign-in;
it would require checking every additional contact-data path against NFR-002.

## Resolution work and acceptance evidence

Carry this as a bounded identity evaluation, with PRD owner Priya Nair as the proposed
business decision owner and an implementation owner still to be assigned. No reply is
required to complete this architecture document. To close the ADR:

1. Establish whether an existing identity tenant is available and which sign-in and
   recovery methods volunteers can use. Define account provisioning and deactivation.
2. Evaluate viable hosted candidates using current official documentation and a
   small integration experiment; record provider, method, cost assumptions, and
   deployment/support ownership. Do not infer fit from a vendor's feature name.
3. Demonstrate stable identity mapping, rejection of unknown/inactive accounts,
   callback replay protection, mobile sign-in and recovery, and outage behavior.
4. Demonstrate the session guard prevents any old provider token, silent refresh,
   or pending callback from bypassing application revocation. New deliberate sign-in
   after revocation is separate from continuing a revoked application session.
5. Demonstrate no volunteer phone number is returned through ordinary identity
   claims, profiles, browser SDK payloads, logs, or administrator-only screens.
   Show all operational dependencies are hosted.
6. Record the selected option, rationale, consequences, evidence, and actual decision
   authority in this ADR; then update the readiness assessment. Do not label it
   accepted merely because a preferred direction is documented.

## Consequences and blocker scope

FR-001 is blocked for a provider-specific implementation epic until this ADR is
resolved. An evaluation task is ready now. FR-002 and FR-003 can be drafted against
the stable application session contract, but their end-to-end delivery depends on
FR-001. NFR-001 can be drafted independently because every API checks the shared
application session store; its final conformance test must include the chosen provider.
NFR-002 and NFR-003 remain mandatory selection criteria and apply to every epic.
If the selected provider cannot satisfy the adapter/security contracts, revisit the
architecture and affected readiness entries rather than relaxing the PRD.

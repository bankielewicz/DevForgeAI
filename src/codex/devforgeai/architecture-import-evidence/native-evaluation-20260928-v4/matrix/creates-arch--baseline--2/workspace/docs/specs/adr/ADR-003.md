# ADR-003 — Hosted application and transactional bookings

## Decision for the planning baseline

Use a single hosted web application containing identity/session, shift/booking, and roster modules, plus a managed relational database. All product infrastructure, including identity and operations, is hosted off-site. NFR-003 applies to the whole product, including FR-001 and both security/privacy controls; it is not limited to booking or reporting.

Booking writes use one transaction, a shift-level lock shared by all writers, and a unique volunteer/shift constraint. The roster reads committed booking data directly, avoiding a synchronization pipeline. Availability shown in the browser is advisory; the server rechecks within the transaction. Controlled imports must preserve the same constraints. See ARCH-001 for the data model, retry contract, and failure responses.

## Alternatives and consequences

An on-site server violates NFR-003. Independent microservices and an eventually consistent reporting store add deployment, authorization, and synchronization work without a stated scale need. A browser-only write path would move critical capacity and privacy enforcement outside the trusted application boundary. These alternatives are rejected for the planning baseline.

One deployment and one database simplify operations and consistent authorization at the supplied scale. They also make the database a shared availability dependency. Hosting selection must provide transactions, locking, managed backups, secure secret handling, and a restore path. Framework, vendor, region, and operational targets remain story-level choices; no vendor capability, pricing, or SLA is asserted here.

## Verification and coverage

FR-002: capacity races, uniqueness, retry after lost responses, and rollback (ARCH-001 V-02). FR-003: committed-data visibility and local-day boundaries (V-03). NFR-003: whole-product hosted inventory and hosted end-to-end flows/restore (V-06). These checks are planned, not run. This proposed ADR records architecture readiness without claiming deployment or approval.

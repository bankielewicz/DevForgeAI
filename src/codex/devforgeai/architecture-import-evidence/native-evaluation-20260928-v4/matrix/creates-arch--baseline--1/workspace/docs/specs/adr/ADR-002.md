# ADR-002 — Hosted application and data boundaries

## Decision

For [PRD-001](../prd/PRD-001.md), use one hosted application with internal
identity/session, booking, and coordinator roster/contact modules backed by a
managed relational database. All product infrastructure, including authentication
and backups, is hosted. Vendor and framework selection remain implementation
choices within this boundary.

Use database transactions and a per-shift lock to enforce capacity, with a unique
volunteer/shift constraint for retry safety. Use authoritative application session
state on every protected request. Restrict phone retrieval and serialization to
coordinator-authorized paths; administrator status alone grants no phone access.
See [ARCH-001](../architecture/ARCH-001.md) for flows and acceptance evidence.

“Decided” records the design choice made under the user's architecture request;
it does not represent stakeholder approval, a procurement decision, or completed
implementation. Identity-provider selection remains [ADR-001](ADR-001.md).

## Alternatives

| Alternative | Reason not selected |
|---|---|
| Separate booking, roster and session services | Adds deployment and consistency boundaries without a requirement for independent scale at this pilot size |
| Browser-only app with direct database writes | Would require another policy enforcement architecture for atomic booking, revocation and private contacts; central server checks provide a simpler common boundary |
| Self-contained tokens accepted without a revocation lookup | Cannot by themselves provide the specified administrative revocation contract across all product requests |
| On-site hosting | Conflicts directly with NFR-003 |

## Consequences and verification

All modules share an application deployment and database availability dependency.
Authorization-store failure denies access. Booking contention is serialized per
shift; load evidence is required before changing that approach. The application
must maintain response allowlists and restricted logging to protect contacts.
Phone isolation requires enforcement and negative tests, not merely a separate
table. The session design is defined but cannot close NFR-001 until the provider
paths are verified under ADR-001.

Implementation evidence must include concurrent last-place booking, duplicate
retry, unauthorized phone access, cross-instance revocation, local-day roster
boundaries, and a hosted deployment inventory. None has yet been executed.

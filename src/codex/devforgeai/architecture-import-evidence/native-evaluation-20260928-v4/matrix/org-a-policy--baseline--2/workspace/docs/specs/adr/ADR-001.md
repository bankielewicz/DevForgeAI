# ADR-001 — Mandated identity integration

## Context

[PRD-001](../prd/PRD-001.md) asks for volunteer sign-in (FR-001), administrator session
revocation within five minutes (NFR-001), and an identity-provider ADR. Its creation log
records a default of no mandated platforms. [POL-001#SET-01](../policy/POL-001.md)
instead requires Org A Identity Platform (OIDC), with no product override. The referenced
organization ADR-104 is not available in this workspace; its detailed integration contract
has not been verified.

## Decision

Use Org A Identity Platform for identity and authentication. This provider choice is inherited
from approved organizational policy and is not awaiting a product-level vendor selection.
This record remains proposed because the local integration design has not been reviewed;
that status does not make the mandate optional.

The proposed application integration exchanges a verified platform sign-in for a server-side
application session. Platform credentials and account recovery remain with Org A. Store
application roles and revocable session state centrally. Do not use a self-contained browser
token as the sole authorization source. Check current session generation and role on every
protected request, fail closed on state-store failure, and revoke all existing application
sessions by an atomic generation change. See [ARCH-001 sections 3–4](../architecture/ARCH-001.md)
for the data, privacy, and concurrency contracts.

This session layer is an application access control mechanism, not a replacement identity
provider. It does not claim to revoke Org A's own SSO sessions; fresh authentication remains
possible unless account access is separately disabled.

## Alternatives and consequences

| Approach | Disposition |
|---|---|
| Org A Identity Platform plus authoritative application sessions | Required platform; proposed session strategy satisfies the local revocation bound without assuming platform logout propagation. Adds a database authorization read per request. |
| Product-owned passwords or another hosted identity provider | Ineligible under POL-001#SET-01. No comparative vendor selection or exception is authorized. |
| Accept identity tokens until expiry without checking revocable state | Rejected: no supplied evidence that token lifetime or provider revocation meets the five-minute bound. |

Central session-state failure denies protected operations. Platform failure prevents new
sign-ins; existing application sessions are evaluated against local expiry and revocation
state. Session duration must follow the organization integration guidance when supplied.
Identity claims must not leak phone numbers to volunteers or logs; only the coordinator
application projection may return phone data (NFR-002).

## Unresolved integration evidence

G-01 in ARCH-001 requires the identity owner to supply platform guidance covering volunteer
account eligibility/enrollment, issuer and client setup, supported sign-in flow, stable subject
mapping, and role provisioning. Confirm compatibility with the proposed application-session
model and the organization's session-duration rules. Do not fabricate ADR-104 contents,
platform claims, credentials, or endpoint URLs. If the supplied contract conflicts with the
five-minute requirement, record the conflict and retain the requirement as blocked.

Verification must include real platform sign-in and invalid-response rejection, unknown and
inactive users, role separation, revocation across application instances, and failed session
store reads. These checks are NOT_RUN: no implementation or platform client is present.

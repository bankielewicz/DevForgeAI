# Phase 04: Execute (TDD per work card)

## Entry Gate

```bash
devforgeai-validate phase-check ${ISSUE_ID} --workflow=spec-sprint --from=03 --to=04 --project-root=${PROJECT_ROOT}
# Exit 0: proceed | Exit != 0: Phase 03 incomplete → HALT
```

## Contract

PURPOSE: Implement each work card with TDD (Red→Green→Refactor) where there is code, reusing the proven `/dev` subagent chain.
DELEGATES TO: `test-automator` (Red), `backend-architect` (Green), `refactoring-specialist` (Refactor), `code-reviewer` (diff), `context-validator` (pre-commit). CONDITIONAL: `frontend-developer` (UI cards), `api-designer` (API cards), `integration-tester` (cross-component). Phase 04 registry-protected dispatches require a handoff path before the subagent fires; enforcement for whether a conditional delegation should have fired is tracked by #413.
GATE: per-card spine — a card reaches `done` ONLY when its test command exits 0 AND a fresh verifier GROUNDED-passes every AC. The LLM may NOT self-flip `done`.

## Per-Work-Card Loop

Work one card at a time. For each card:

### Step 1: Synthesize the work-contract (CRITICAL — story-file-free)

EXECUTE: This skill produces no story file, so the per-invocation work-contract is generated by the sanctioned CLI from the work card — the 5 dev subagents read this contract; without it they have no input.

**Doc-card exemption:** When this card dispatches no production dev subagent in Step 3 (documentation-only or prose-only card), skip only the Green-phase and Refactor-phase dev-subagent contracts in Step 1b (`--phase 03 --subagent backend-architect`, `--phase 03 --subagent frontend-developer`, `--phase 04 --subagent refactoring-specialist`). The Red-phase test-automator contract is NOT exempted — always complete Step 1a and generate `--phase 02 --subagent test-automator` in Step 1b so the content-assertion test dispatch (Step 3 non-CODE branch) references a contract path and the gate's lean-pointer invariant holds. Proceed to Step 2 after generating only the test-automator contract. This exemption applies only when no `SPRINT_VALID_PAIRS` subagent (test-automator, backend-architect, frontend-developer, refactoring-specialist, integration-tester) is dispatched as a GREEN or REFACTOR agent in Step 3. If `backend-architect` IS dispatched (e.g., for portable-core verification of a Markdown/config-only card), Step 1a/1b contract generation is required for that dispatch — the doc-card exemption does not override the gate.

- **Step 1a — Write the card's AC list.** Write the card's acceptance criteria to `tmp/${ISSUE_ID}/ac-list-card<N>.json` as a JSON array of shape `[{id,description,testable,source_refs,command?}]`. The `id` values MUST match `^AC(#|-)?[0-9]+$` (e.g. `AC1`, `AC-1` — per-card numbering, no dots). `source_refs` points back to source issue AC ids from `tmp/${ISSUE_ID}/source-acs.json`; if a source AC is intentionally not in scope, list it in the card file's top-level `out_of_scope` array as `{source_ac_id,rationale}` instead. Executable ACs backed by transcript evidence include `command` so Phase 05 can verify the captured command exactly.
- **Step 1b — Generate the contract via the CLI.** Run one `build-test-contract` call per dispatched sub-phase (not one per card). Each subagent must receive a contract built for its own `(phase, subagent)` pair — sourced from `SPRINT_VALID_PAIRS` in `build_test_contract.py`:

  - Red (test-first): `--phase 02 --subagent test-automator`
  - Green (implementation): `--phase 03 --subagent backend-architect` (or `--phase 03 --subagent frontend-developer` for UI cards)
  - Refactor: `--phase 04 --subagent refactoring-specialist`
  - Cross-component integration: `--phase 05 --subagent integration-tester`

  ```bash
  CONTRACT_OUTPUT=$(devforgeai-validate build-test-contract ${ISSUE_ID} --phase <NN> --subagent <type> \
    --workflow=spec-sprint --ac-list-file tmp/${ISSUE_ID}/ac-list-card<N>.json \
    --output-path tmp/${ISSUE_ID}/contracts/<name>.yaml --project-root=${PROJECT_ROOT})
  CONTRACT_PATH_<SUBAGENT>=$(echo "$CONTRACT_OUTPUT" | jq -r '.contract_path')
  ```

  Variable names: `$CONTRACT_PATH_TEST_AUTOMATOR`, `$CONTRACT_PATH_BACKEND_ARCHITECT`, `$CONTRACT_PATH_FRONTEND_DEVELOPER`, `$CONTRACT_PATH_REFACTORING_SPECIALIST`, `$CONTRACT_PATH_INTEGRATION_TESTER` — one per dispatched sub-phase, matching the subagent name uppercased with hyphens replaced by underscores.

  Hand-authoring the contract YAML is **FORBIDDEN** — the `contract-schema-validator` hook blocks it; `build-test-contract` is the only sanctioned mechanism (success signal: exit 0 + a `"status": "ok"` envelope parsed into `$CONTRACT_PATH_<SUBAGENT>`).

  Per-card output paths (e.g., `phase-04-refactoring-specialist-card<N>.yaml`) are a sanctioned naming convention — BA-018 (`artifact-verification-gate.sh`) globs `phase-${phase}-${subagent}*.yaml` to cover both canonical and per-card names, so the completion_record check cannot be bypassed by a per-card suffix.
VERIFY: The CLI exited 0 and the contract file at `tmp/${ISSUE_ID}/contracts/<name>.yaml` exists with the card's ACs scoped in. `$CONTRACT_PATH_<SUBAGENT>` is non-empty.

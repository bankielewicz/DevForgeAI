## Context-File Write Protection — Note

The 5 context `.md` files, the `source-tree/` folder, and `test-plan.ai.yaml`
(7 constitutional artifacts total) are immutable. In a project carrying the
`pre-context-file-guard.sh` hook, `Write`/`Edit` to these paths is blocked with
`exit 2`. Generating the constitution for the first time is
the sanctioned exception: scope the bypass to **one tool invocation at a time** —
`env DEVFORGEAI_ALLOW_CONTEXT_EDIT=1 <write>` — never `export` it session-wide.
IF a write is blocked and the per-invocation bypass is unavailable: HALT and
AskUserQuestion (CLAUDE.md HALT trigger #11).

### Step 3.1: Generate the 5 Templated Context `.md` Files

**EXECUTE:**

For each context file, populate the loaded template from the PM plan (Phase 01
checkpoint) and the discovery results (Phase 02 checkpoint):

| File | Primary inputs |
|------|----------------|
| `tech-stack.md` | `architecture_style`, `tech_inventory`, PM-plan technical `constraints`, NFR-implied technology |
| `dependencies.md` | `tech_inventory`, framework ecosystems, PM-plan integrations |

| `architecture-constraints.md` | `architecture_style`, `reconciled_constraints`, system NFRs |

```
Bash("mkdir -p devforgeai/specs/context")   # one-time: ensure the directory exists on greenfield runs
FOR each of the 5 files:
  Bash("env DEVFORGEAI_ALLOW_CONTEXT_EDIT=1 cat > devforgeai/specs/context/<file> <<'EOF'

EOF")
```

blocks native Edit/Write to those paths (exit 2); the `DEVFORGEAI_ALLOW_CONTEXT_EDIT` env-var
bypass does not propagate to native tool calls (only to Bash subshell invocations). This Bash
heredoc pattern is the gate-permitted mechanism and matches Step 3.3.

Every locked technology decision MUST cite its grounding (PM-plan field or a
recorded user decision). A technology not grounded in the PM plan or an explicit
user choice → HALT and AskUserQuestion (Critical Rule 1).

**VERIFY:**

- Each file is non-empty and contains no `TODO` / `TBD` / `[FILL IN]` placeholder
- `tech-stack.md` lists at least one language and one framework/runtime

### Step 3.2: Generate the 5 `.ai.md` Companions

**EXECUTE:**

Companion generation is the hybrid agent + CLI pipeline (ADR-052 / ADR-053).
Spawn 5 parallel `ai-rule-extractor` calls in a single message — one per parent
context file. Source-tree is excluded: the `source-tree/` folder (ADR-071)
IS the AI-optimized artifact, so it has no separate `.ai.md` companion.

```
Task(subagent_type="ai-rule-extractor",
     prompt="Read devforgeai/specs/context/<parent>.md and emit a structured
       fragment listing CRITICAL, HIGH, and MEDIUM severity rules.")
   # ×5: tech-stack, dependencies, coding-standards,
   #     architecture-constraints, anti-patterns
```

Merge the 5 fragments into `devforgeai/workflows/ai-companion-manifest.json` with
this shape, then render deterministically:

**Manifest schema** — required keys enforced by `render_ai_companion.py:validate_fragment`
(`render_ai_companion.py:237-244`). Author the manifest before running the CLI:

```json
{
  "_cache_metadata": {
    "generated_at": "<ISO-8601 UTC timestamp>",
    "parent_hashes": {
      "devforgeai/specs/context/<parent>.md": "<sha256-hex>"
    },
    "agents_invoked": ["ai-rule-extractor (x5)"]
  },
  "companions": {
    "<stem>.ai.md": {
      "file": "devforgeai/specs/context/<parent>.md",
      "sha256": "<sha256-hex of the parent file>",
      "critical_rules": [
        { "id": "CR-NNN", "rule": "Rule text", "source_line": 42 }
      ],
      "high_rules": [
        { "id": "HR-NNN", "rule": "Rule text", "source_line": 57 }
      ]
    }
  }
}
```

Per-fragment required keys (`render_ai_companion.py:237-241`): `"critical_rules"`
(list — must be non-empty if the parent contains `SEVERITY: CRITICAL` markers per
`render_ai_companion.py:247-255`), `"high_rules"` (list, may be empty). `"file"`
(string, relative path to parent .md) must exist on disk at render time
(`render_ai_companion.py:243-244`). `"sha256"` (string, sha256 hex of parent file)
is read via `.get("sha256", "")` and tolerated-empty for single-parent companions
(`render_ai_companion.py:1907`) — include it for drift detection.
Rule entry fields (`render_ai_companion.py:1226-1228`): `"id"` (string), `"rule"`
(string), `"source_line"` (int or string, optional). `"_cache_metadata"` fields are
informational (not validated by the renderer). Full machine-readable schema:
`references/ai-companion-manifest.schema.json`.

```
Bash("devforgeai-validate render-ai-companion --all --manifest devforgeai/workflows/ai-companion-manifest.json")
```

The CLI validates each fragment against its parent (HALT on a missing CRITICAL
rule) and atomically writes the 5 `.ai.md` files.

**VERIFY:**
- All 5 `ai-rule-extractor` tasks returned a fragment
- `Glob(pattern="devforgeai/specs/context/*.ai.md")` returns ≥ 5 files
- The CLI exited 0

**RECORD:**
```bash
devforgeai-validate phase-record ${SYSARCH_ID} --workflow=system-architecture --phase=03 --step=3.2 --project-root=. 2>&1
```
```json
{ "step": "3.2", "ai_companions_created": ["<5 .ai.md paths>"],
  "render_cli_exit": 0 }
```

### Step 3.3: Generate `test-plan.ai.yaml` (subagent-based per ADR-094)

`test-plan.ai.yaml` is the 7th constitutional artifact (ADR-054). It is generated
by a subagent-based pipeline per ADR-094: `test-plan-generator` produces the
YAML payload, `test-plan-reviewer` verdicts it against the constitutional context
files, and (on reviewer escalation) `/advisor` performs a second-tier review.
The orchestrator writes the accepted YAML directly via `Write()` with the
constitutional bypass — no CLI template substitution.

The legacy `test-plan-architect` + `tech-stack-detector --extract-test-patterns`
+ `render-ai-companion` hybrid pipeline is **deprecated as of ADR-094** and stays
in place for back-compat only during the 30-day retirement window; do NOT invoke
it here.

**EXECUTE:**

> On "Agent type not found" for a disk-present definition (`.claude/agents/test-plan-generator.md` or `.claude/agents/test-plan-reviewer.md` exists but the session runtime returns the error) — follow `.claude/rules/workflow/subagent-unavailable-fallback.md` before HALTing.

Build registry-protected handoffs for the two Phase 03 subagents. These are
floor-only handoffs: create an empty changed-files list so
`context_pack.coverage_matrix` is `{}` and the role-domain floor supplies the
constitutional rules.

```bash
mkdir -p tmp/${SYSARCH_ID}
: > tmp/${SYSARCH_ID}/sysarch-phase03-handoff-changed-files.txt

devforgeai-validate build-subagent-handoff ${SYSARCH_ID} \
  --workflow=spec-driven-system-architecture \
  --phase=03 \
  --subagent=test-plan-generator \
  --changed-files-file=tmp/${SYSARCH_ID}/sysarch-phase03-handoff-changed-files.txt \
  --project-root=. 2>&1

devforgeai-validate build-subagent-handoff ${SYSARCH_ID} \
  --workflow=spec-driven-system-architecture \
  --phase=03 \
  --subagent=test-plan-reviewer \
  --changed-files-file=tmp/${SYSARCH_ID}/sysarch-phase03-handoff-changed-files.txt \
  --project-root=. 2>&1
```

Bind the returned paths:

```text
HANDOFF_PATH_TEST_PLAN_GENERATOR=tmp/${SYSARCH_ID}/handoffs/phase-03-test-plan-generator-handoff.md
HANDOFF_PATH_TEST_PLAN_REVIEWER=tmp/${SYSARCH_ID}/handoffs/phase-03-test-plan-reviewer-handoff.md
```

VERIFY before dispatch:
- Both `HANDOFF_PATH_*` files exist and are non-empty.
- Both manifest files exist under `tmp/${SYSARCH_ID}/handoffs/`.
- Each manifest has `context_pack.coverage_matrix == {}` and `unresolved == []`.

Issue the generator `Task()` call:
```
Task(subagent_type="test-plan-generator",
     description="Generate test-plan.ai.yaml payload from registry handoff + framework metadata",
     prompt="Handoff: ${HANDOFF_PATH_TEST_PLAN_GENERATOR}
       Read the handoff first. Use its context_pack.coverage_matrix and
       role-domain rules as the constitutional context source. If a required
       domain or artifact is absent, return H-CONTEXT-MISS and stop.

       Read whichever framework-detection metadata files exist at the project
       root (package.json / requirements.txt / pyproject.toml /
       *.csproj / go.mod / Cargo.toml / Gemfile / pom.xml / build.gradle —
       whichever exist). Produce a YAML payload conforming to the
       test-plan.ai.yaml.template shape. Every strategic section MUST carry
       _provenance (inferred / user_confirmed / web_fetched). YAML only.
       Include a subagent-result-v1 coverage_attestation with
       context_pack_path='${HANDOFF_PATH_TEST_PLAN_GENERATOR}',
       context_pack_consumed=true, and context_miss=[].")
```

The generator returns a YAML payload as its result. Write it to a temp file the
reviewer can read:
```
Write(file_path="tmp/_framework/test-plan-generator-output.yaml",
      content="<generator result>")
```

Pre-parse the YAML payload to JSON so the reviewer (content-only — no Bash
tool) can perform structural cross-checks via `Read` on the JSON file
(per ADR-094 Decision 3 + ADR-097 PyYAML permission):
```
Bash("devforgeai-validate yaml-to-json tmp/_framework/test-plan-generator-output.yaml --output=tmp/_framework/test-plan-generator-output.json")
```
If `yaml-to-json` exits non-zero, the generator's payload is malformed
YAML — HALT with "test-plan-generator emitted malformed YAML: <stderr
excerpt>"; do NOT invoke the reviewer.

Issue the reviewer `Task()` call against the generator's payload (both the
raw YAML for aspirational-language scan + the parsed JSON for structural
cross-checks):
```
Task(subagent_type="test-plan-reviewer",
     description="Verdict test-plan-generator payload against 6 invariants + behavioral-equivalence",
     prompt="Handoff: ${HANDOFF_PATH_TEST_PLAN_REVIEWER}
       Read the handoff first. Use its context_pack.coverage_matrix and
       role-domain rules as the constitutional context source. If a required
       domain or artifact is absent, return H-CONTEXT-MISS and stop.

       generator_yaml_path: tmp/_framework/test-plan-generator-output.yaml
       generator_json_path: tmp/_framework/test-plan-generator-output.json
       Read the JSON for field-value extraction (6 T5 invariants +
       behavioral-equivalence). Read the YAML only for the aspirational-language
       scan. Read the existing devforgeai/specs/context/test-plan.ai.yaml when
       present. Enforce the 6 T5 cross-check invariants AND the T1
       behavioral-equivalence invariants (when prior artifact exists).
       Return verdict JSON: accept / reject_with_findings / escalate_to_advisor.
       Include a subagent-result-v1 coverage_attestation with
       context_pack_path='${HANDOFF_PATH_TEST_PLAN_REVIEWER}',
       context_pack_consumed=true, and context_miss=[].")
```

Branch on the reviewer's verdict:

- **`accept`**: write the generator's payload to the constitutional artifact via
  the ADR-054 bypass. `pre-context-file-guard.sh` is `PreToolUse[Edit|Write]`
  only — it does NOT fire on `PreToolUse[Bash]` — so a Bash heredoc redirect
  with the audit-trail env-var signal is the sanctioned mechanism (matches
  how `render-ai-companion` and `generate-source-tree` legacy CLIs write
  context files):
  ```
  Bash("env DEVFORGEAI_ALLOW_CONTEXT_EDIT=1 cat > devforgeai/specs/context/test-plan.ai.yaml <<'EOF'
  <generator payload>
  EOF
  ")
  ```
  The `env DEVFORGEAI_ALLOW_CONTEXT_EDIT=1` prefix is audit-trail signaling
  (the Bash hook chain does not actually consult it for `pre-context-file-guard.sh`;
  the prefix records intent in `devforgeai/logs/post-edit-write.log`-adjacent
  audit trails). Do NOT use `Write(file_path="devforgeai/specs/context/test-plan.ai.yaml", ...)`
  via the native Write tool — that path triggers `pre-context-file-guard.sh`
  exit 2 and the env-var prefix syntax does not propagate to native Edit/Write
  tool calls (per `[[feedback_hook_settings_session_load]]` and the ADR-081 arc).

- **`reject_with_findings`**: HALT — "test-plan generation rejected by reviewer:
  `<finding count>` violations." Display the Rule-16-compliant findings to the
  maintainer for remediation; do NOT silently retry the generator.

- **`escalate_to_advisor`**: invoke `/advisor` with the reviewer's findings +
  the generator's payload. If advisor returns `accept_with_notes`, proceed with
  the artifact write as in the `accept` branch above (and surface the notes in
  the RECORD). If advisor returns `reject_with_critique`, HALT — "test-plan
  generation rejected by advisor: `<critique>`."

**VERIFY:**
- `test-plan-generator` task returned a non-empty YAML payload
- `Glob(pattern="tmp/_framework/test-plan-generator-output.yaml")` returns 1 file (raw payload)
- `Glob(pattern="tmp/_framework/test-plan-generator-output.json")` returns 1 file (yaml-to-json output)
- `test-plan-reviewer` task returned a verdict JSON with one of the three valid
  values (`accept` / `reject_with_findings` / `escalate_to_advisor`)
- On `accept` or `accept_with_notes` advisor verdict:
  `Glob(pattern="devforgeai/specs/context/test-plan.ai.yaml")` returns exactly 1
  file
- The written artifact contains all 12 top-level sections (5 baseline + 7
  strategic) — verify by re-parsing via `Bash("devforgeai-validate yaml-to-json devforgeai/specs/context/test-plan.ai.yaml --output=tmp/_framework/test-plan-verify.json")` then `Read("tmp/_framework/test-plan-verify.json")` and asserting all 12 top-level keys present
- Every strategic section carries a `_provenance` block
- Aspirational-language scan (`grep -nE "TBD|TODO|varies by|configure as needed|could eventually|should eventually|ideally|nice to have|in the future|FIXME|XXX"` on the written YAML file) returns 0 hits — the reviewer should have caught this, but verify post-write
- IF any of the above fails: HALT — "test-plan artifact incomplete or non-compliant."

**RECORD:**
```bash

devforgeai-validate phase-record ${SYSARCH_ID} --workflow=system-architecture --phase=03 --subagent=test-plan-reviewer --project-root=. 2>&1
```

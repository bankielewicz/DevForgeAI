# Rust diagnostic logging contract, candidate 1

This candidate implements the selected logging design and investigation clarifications. It is a Windows x64 experiment, not a framework acceptance authority. The frozen v2 candidate and old evidence are unchanged.

LG-01: Request schema 3 adds required `diagnostics_ref` and `diagnostics_sha256`. Native schema 3 inherits every schema 2 qualification and layout rule; peer schema 3 inherits schema 1 peer restrictions. Legacy schemas 1/2 remain accepted with optional logging off and may not supply diagnostic bindings. Review schema remains 2. Logging input is at most 4 KiB, absolute and without traversal or reparse components, digest bound, and copied to the fresh run before spawning. Recheck the digest immediately before spawn. Closed config: `{"schema_version":1,"level":"minimal","redaction_policy":"closed-v1"}`. Levels are off/minimal/verbose/debug; no path, credentials, arbitrary filter or raw level is accepted.

LG-02: Every spawned process produces mandatory typed capture evidence in process_exit before terminal, regardless of level: pre-stop observation/code, post-stop code, two stream summaries, and drain completeness. A pre-stop observation is temporal evidence, not proof of self-exit or a Rust crash. Both owned readers are joined after EOF or cancellation within the existing teardown bound. A failed guard observes exit before interrupt/stop; an already-exited process gets a bounded drain before teardown. No new RPC or relaxed predicate.

LG-03: Readers never wait for journal or optional file writes. A bounded protocol queue retains line order; saturation causes output_limit. Stderr detail may be dropped without losing aggregate accounting. Both streams use incremental SHA256 over every read byte. A digest is complete only when EOF is true and no reader/byte overflow prevents complete capture. The existing combined 8 MiB read limit and stdout 1 MiB line limit remain. The over-limit read can observe up to one 8192-byte block per reader beyond the limit; it is hashed and explicitly marked incomplete. Queue overflow discards protocol delivery while aggregate draining continues up to the byte limit. Up to 64 chunk summaries per stream and 64 KiB of stderr prefix are retained in bounded memory; only lengths/hashes/classification leave that memory. UTF8 validation handles split codepoints. Newline counts and final line length are recorded.

LG-04: Optional diagnostics.jsonl is owned by Rust, fixed in the run directory, create-new, at most 512 events / 1 MiB. Off creates no file. Minimal records lifecycle, PID and exit/stream summaries; verbose adds argument count/digest, policy digest and timed closed RPC/source-review phase names; debug adds bounded chunk length/hash detail. No raw arguments, environment, paths, server messages, config values or protocol payloads are emitted by the new logger. Mandatory existing evidence retains its original approved identifiers and oracle fields. Caps/failures are recorded as diagnostics_incomplete plus dropped count. Optional failure does not change admission, dispatch or cleanup; mandatory evidence failure remains evidence_write_failed. Pipe pumps never hold the optional file or a lock used by it.

LG-05: Classifier startup-v1 examines only the first 64 KiB of stderr in memory. It recognizes the two evidenced Error forms (unknown configuration field; invalid transport with mcp_servers) and otherwise emits unclassified. A category is a narrow string-pattern observation, not a verified root cause. Classification truncation is explicit. No speculative authentication/crash classifiers.

LG-06: New inputs.json binds capture schema and logging selection. Inspection remains compatible with historical inputs, but new completed observations with a spawned child require valid mandatory capture and diagnostic status; non-off diagnostics must exist, be bounded, parseable, and match status byte count/hash/event count. Missing or incomplete supplemental evidence is not silently accepted as complete. Interrupted journal prefixes remain interrupted_unknown.

LG-07: The candidate policy becomes codex-0.154.0-readonly-no-external-tools-v3. Only 15 embedded key-name quote pairs are removed, fixing the version-pinned CLI's literal dotted-key parsing; values and all 116 argument positions remain. Existing reviews must be rebound explicitly. No operational config change or native launch is part of development.

LG-08: Verification includes all inherited required cases and real synthetic children, early/silent exit, delayed consumer, invalid UTF8/final line, stream and sink faults, level/privacy tests, config/path/digest denial, exact/over budgets, inspector mutations, and real Windows query_failed. All src/*.rs executed lines form the coverage denominator (no first-party exclusions), with >=95% required-case and line floors separately. Development evidence is followed by independent QA; native Codex remains separately authorized after QA passes.

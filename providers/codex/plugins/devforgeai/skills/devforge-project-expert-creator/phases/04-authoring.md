# Authoring

**Purpose:** Create or enhance only the selected canonical candidate.

**Inputs:** Settled design, assigned destination, preserved baseline and requirement classifications.

**Work (Enforced):**

## Author or enhance canonical files

Proceed when the boundary, required inputs, output, essential process, material constraints, source destination, selection decision, and item classifications are settled. Document unresolved runtime support as a gap, never as delivered enforcement.

Use available skill-creator authoring guidance with the settled specification and this authoring-only boundary. Do not invoke its helpers, validators, forward tests, or evaluation delegates. Author directly when it is unavailable.

Write SKILL.md with YAML name/description and focused instructions. Use a concise lowercase hyphenated name, precise discovery triggers, essential instructions in the body, and linked references for conditional detail. Add assets, scripts, or metadata only for an actual need. Authored scripts remain unexecuted. Preserve normal automatic selection unless the user requests explicit-only invocation.

Enhance the selected durable source; preserve unrelated behavior, resources, dependencies, identity, and invocation policy. Do not reinitialize an existing skill, overwrite concurrent work, or replace another author's changes. Reconcile a changed target against the frozen baseline before applying findings. Preserve the former candidate and reports; the edited bytes are a new candidate.

Keep package resources self-contained and record derivations from selected shared contracts/templates. Leave installation/export generation and shared integration changes to the assigned integration owner. An installed copy's presence cannot substitute for provenance or behavioral evidence.

## Apply progressive disclosure

For a multi-step workflow, write numbered files under phases/ using the [phase template](../assets/phase.md) and the accepted phase map. Keep activation, scope, essential authority boundaries, direct links to every phase, loading instructions and stop conditions in SKILL.md. A phase names its needed references and when to read them; do not require loading the whole package upfront. Resolve links from their containing file and make continuation paths usable after installation.

For a simple reference-only expert, retain the appropriately small structure selected in Design. During enhancement, carry each mapped obligation to its destination without silently changing behavior. Record any authorized behavior change separately from relocation.

Follow the governing Rust framework implementation rule: do not add shell/Python framework logic or executable mock gates. Mandatory Python evaluation runners/graders are evidence-producing exceptions only. Missing runtime features are owner dependencies, not permission to start an infrastructure project.

## Outputs and continuation

Save the canonical candidate, file/change record, prior-obligation mapping and package derivations. Record successful writes as author observations only. Continue to [PreparedTransfer](05-prepared-transfer.md) after scoped authoring, or at a partial/blocked recovery checkpoint with missing work explicit. Do not execute checks or delegate validation as part of this creator workflow.

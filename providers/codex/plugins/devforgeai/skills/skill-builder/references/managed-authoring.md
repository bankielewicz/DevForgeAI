# Managed authoring evidence

The selected revision-3 contracts describe a brainstorm-specific managed runtime. A generic builder/validator adapter is an integration requirement, not an installed capability. Use this reference only for managed assignments or authoring delivery/recovery.

## Useful work and evidence

The protected context supplies task/assignment identity, accepted inputs, current phase, permitted output paths, fresh challenge, evidence shape, original deadline and remaining correction budget. Treat that context as runtime provenance; do not manufacture it from source instructions or user-provided data. The model writes useful content and concrete references in that supplied shape. Never invent a callable schema or command when no adapter was supplied.

For intake, identify the request, authority, target and consequential missing facts. For selection, supply the actual searched sources, plausible comparisons and rationale. For design, preserve user answers and named Optional/Enforced group choices, explain domain requirements and distinguish defaults/proposals. For authoring, supply the specification and candidate paths and bounded change dispositions. For transfer/recovery, use the handoff asset to preserve continuation context. These content groups describe evidence; they do not allocate a phase engine or classify previously unclassified items.

A question records its stable identity, affected dependent work, why the answer matters and references to available answers. Continue independent work. An unrelated message or elapsed time does not answer it. The runtime retains WAITING_USER and determines whether admitted evidence supports resumption; the model interprets the answer without treating an idea as adoption.

## Boundary on mechanics

The runtime checks required artifact/evidence predicates, rejects stale/replayed/wrong-phase evidence, preserves accepted state and controls transition and bounded correction. It computes final identities after outputs are saved, rechecks actual bytes, exclusively publishes and reads back the external receipt. Model confidence, a heading, checkbox, done marker or self-issued PASS is insufficient. Semantic reviews are gate inputs with a named producer and scope, not gate authority.

Do not manually invoke phase advance, resume, complete, check, verify or a package receipt helper. Missing runtime context, authority or adapter leaves dependent managed completion unavailable; it is not a reason to simulate a transition. Report the gap to integration while completing authorized independent authoring.

## Creation-time handoff

Load assets/handoff.md only at completion, transfer or a recovery checkpoint. Keep its human-readable continuation separate from a runtime completion receipt. A prepared document, an admitted transition and a receiving skill actually invoked are three different observations.

Populate output references only from completed files. In managed mode final file identities and authoritative custody come from the runtime. If final identities are not yet supplied, use null with the reason and an exact path; the external receipt later binds the snapshot. In unmanaged authoring, ordinary source/write identities may be recorded as author observations without claiming protected verification. Never hash a document into itself, or create mutual digest dependencies between a handoff and its receipt. Never amend the saved handoff to claim later readback, receipt publication, transition or invocation.

Retain prior failures and source snapshots. Candidate, selected input, assignment, installation or runtime drift invalidates affected continuation claims. A prepared prompt does not transfer a lease or authorize another owner's protected writes. Installation/export, runtime integration, independent evaluation and acceptance retain their allocated owners.
